# ② 对话分块

> 代码：`src/StarGameAI/Core/Dialogue.cs`（模型 + 存储）、`DialogueRouter.cs`（路由）
> 配置：`config/dialogue.json`
> 页面：后台 `#dialogue`（对话分块）

一句话：**分清"谁在跟谁聊哪件事"，否则一定会答错人。**

---

## 问题的本质

群聊里发生的每一句，实际上都在问一个问题：**这句是在跟我说吗？**

原来的做法是"取最近 24 条历史，塞给模型，指望它自己分清"。
这一层使用**指代消解**解决：先确定归属，再生成。

---

## 两维正交（这一节是整层的设计地基）

```
Entity（谁）   —— 全局，跨 scope、跨块。画像、称谓、记忆归属都挂这
Block（事）    —— 每个 scope 内多块并存。只是"上下文边界"，不持有画像
交叉点         —— Block.Participants 是 entity_id（QQ 号）的引用列表
```

**为什么必须分开建模**：

- 人是全局的。同一个人在私聊和三个群里都是同一个 QQ 号，画像不该复制三份。
- 事是局部的。这个群在聊接入方案、那个群在聊游戏，上下文边界不同。

因为正交，"同一个人同时两条主线"**不是需要取舍的设计决策**，而是数据模型天然允许的状态。

> 角色分界：**人提供"谁"，事提供"上下文边界"。**

## 块模型

```jsonc
{
  "id": "b1234abcd",
  "scope": "group:100001",
  "state": "one_to_one | open_topic | cold | closed",
  "participants": ["10001", "10003"],   // entity_id 引用
  "owner": "10001",                          // one_to_one 时是"跟我说话的那个人"
  "last_user_id": "10001",                   // 这块最后一条是谁发的
  "topic": "接入方案选型",
  "created_at": 0, "last_active_at": 0, "message_count": 0,
  "message_ids": ["..."]
}
```

### `state` 直接导出回复形态

| state | 含义 | 回复形态 |
|---|---|---|
| `one_to_one` | 一个人在跟我说 | 私聊形态，不点名 |
| `open_topic` | 多人在聊同一件事，我可以插 | 群形态，对大家说 |
| `cold` | 一段时间没动静 | 压成摘要（待实现） |
| `closed` | 归档 | 只在深挖时翻 |

**这是"保留对群说话能力"的实现方式**——不需要额外的"广播开关"，块的结构自己就说清楚了。

## 路由：规则优先，模型兜底，判不了就静默

```
规则信号累加
   ├─ 最高分 ≥ min_confidence → continue(那块)
   ├─ 不到门槛 → 问模型
   │     ├─ "编号" 且够置信 → continue
   │     ├─ "new"  且够置信 → new_block
   │     └─ "unknown" / 置信不够 → unresolved
   └─ 没有任何块 → new_block
```

### 六个规则信号（全部可配）

| 信号 | 默认权重 | 说明 |
|---|---|---|
| **同一个人接着说** | 0.45 | 现场最强、最便宜的信号 |
| reply 同一块 | 0.40 | `InReplyTo` 命中块内消息 |
| @ 同一个人 | 0.50 | 消息里 @ 了块里的参与者 |
| 实体重叠 | 0.25 | 消息里提到块里的某人名字 |
| 指代词 | 0.30 | 这个 / 那个 / 刚才 / 她… |
| 时间接近 | 0.20 | 距该块上次活动越近越高 |

> **「同一个人接着说」是实测补上的。** 第一版只有后五个信号，4 条消息里 3 条判不了（75%）——
> 「嗯，我看看」这种短句既没 reply、也没 @、也没指代词，只靠"时间接近 0.20"永远够不到 0.60。
> 补上之后同一个用例的判不了比例从 75% 降到 25%，而且剩下的那 1 条是**正确地**判不了。

### 三分类必须分清

模型输出 `block` 字段有三个合法值：

| 值 | 含义 | 处理 |
|---|---|---|
| `"<编号>"` | 明确延续某块 | 置信够 → continue |
| `"new"` | 明确是新话题 | **置信够**才 new_block |
| `"unknown"` | 看不出来 | 直接 unresolved，不管置信度 |

> 第一版把"看不出来"和"新话题"混成一个兜底词 `none`，而且 `new` 没受置信度约束。
> 结果模型回一句「仅发图片，无文字线索，难判断归属」confidence=30，照样开新块——
> 某个群一天长出 57 个块，而"判不了比例"被算成了 0.7%（假象）。
>
> **教训：允许说"我不知道"这件事，必须在数据结构上体现出来，不能靠 prompt 嘱咐。**

## 当前状态：`observe` 模式

```jsonc
{ "mode": "observe" }   // off | observe | decide
```

`observe` 下：**只记录归属判定与块结构，回复仍然走原来的路径**。一行配置可切换。

**为什么先观测**：分块器是这套方案里唯一真正"新"的算法。它错了后面全错，
而且**错了极难定位**——你看到的现象还是"又答错人了"，根因却藏在分块里。

所以先跑几天，看两个数：

| 指标 | 判据 |
|---|---|
| `unresolved_rate` 判不了比例 | **> 40% 说明分块器不可用，方案前提不成立** |
| 人工抽检准确率 | 随机看几个块，切得对不对 |

达标后再切 `decide`：门改成 `RouteAsync`，上下文改成 `BuildThreadView`（只取该块的消息）。

## 审计与人工纠正

每次判定写一条 `data/audit/dialogue.jsonl`：

```json
{ "ts": ..., "scope": "...", "message_id": "...",
  "decision": "continue|new_block|unresolved",
  "block_id": "...", "confidence": 0.65,
  "by": "rule|model", "why": "...",
  "candidates": { "b1234": 0.65 }, "ms": 12, "mode": "observe" }
```

判不了的消息进 `dialogue/<scope>.json` 的 `unresolved` 池，保留 `unresolved_keep_hours`。

后台可以**人工归位**：给一条判不了的消息选一个已有块，或"新建一块来装它"。
这既是清账，也是在给阈值标定提供真实样本。

## 生命周期

| 阶段 | 触发 | 动作 |
|---|---|---|
| hot → cold | 超过 `hot_idle_seconds` 没新消息 | 标 `cold`（暂不压缩） |
| 超出 `max_hot_blocks` | 同时活跃块太多 | 最久没动静的转 cold |
| 超出 `max_blocks_per_scope` | 一个 scope 块太多 | 按 `last_active_at` 砍末尾 |

> `cold` 摘要压缩（接 `Consolidator`）**还没实现**，见路线图。

## 配置（`config/dialogue.json`）

| 参数 | 默认 | 作用 |
|---|---|---|
| `mode` | `observe` | off / observe / decide |
| `use_model` | true | 模糊时是否问模型 |
| `min_confidence` | 0.60 | 低于此 → 判不了 |
| `gap_seconds_new_block` | 180 | 距上次活动超过这么久就不倾向延续 |
| `max_hot_blocks` | 6 | 同时热块上限 |
| `w_*` | 见上表 | 六个信号权重 |
| `hot_idle_seconds` | 600 | 多久转冷 |
| `unresolved_keep_hours` | 24 | 未归属消息保留 |
| `max_blocks_per_scope` | 60 | 单 scope 块上限 |

## 常见故障

| 现象 | 原因 |
|---|---|
| 块数量爆炸 | `min_confidence` 太低 / `new` 没受置信度约束（旧版本 bug） |
| 判不了比例 > 40% | 信号权重不够；先看审计里的 `candidates` 打分 |
| 一直判不了 | `use_model=false` 且规则信号够不到门槛 |
| 别人插话被归到错的人 | 应有的行为——`unresolved`。人工归位或调低门槛 |
| 块时间轴看不出规律 | 看图：同一话题分成两块说明某信号太弱 |
