# ⑧ 思考层：没人说话时，它在想什么

> 代码：`src/StarGameAI/Core/IdeaEngine.cs`（约 1600 行）
> 子 AI：`IntentAgent.cs` / `WeightAgent.cs`
> 配置：`config/idea.json`
> 页面：后台 `#idea`（思想层）

这是整个项目里最复杂的一层，也是唯一"没有输入也要运转"的一层。
它解决的问题是：**一个只在被叫到时才反应的 AI，不算有自我。**

---

## 一句话概括

每 N 分钟，它问自己三个问题：

1. **此刻我有没有一个具体的动机？** —— 没有就不发散了（省两次调用）
2. **对方要什么 / 我自己在意什么？** —— 两路开始发散
3. **所以我现在该做什么？** —— 三档：什么都不做 / 加权重 / 真的做一件事

---

## 分七段

```
① 触发判断      定时到了？预算够吗？有新输入吗？空闲够久吗？
② 意图判定      有没有具体动机？（子 AI 1 次调用）
③ 双路发散      上下文那一路 + 记忆碎片那一路（各 1 次调用）
④ 合成思想      两路念头合并成一份
⑤ 收敛          压成 [答复] + [意图]（1 次调用）
⑥ 加权归并      把新意向并进"还没做"的集合（子 AI 1 次调用，按需）
⑦ 准入 + 落定   七道闸 → 执行 → 记账
```

最省的一轮是**只花 1 次调用**（意图判定就说"没动机"）；最贵的一轮 5 次。

---

## ① 触发判断：不该想的时候一次都不调

| 条件 | 为什么 |
|---|---|
| `idea.enabled` + `idea.think.enabled` | 总开关 / 这个子层的开关 |
| 本小时轮次 < `max_rounds_per_hour` | 成本闸门 |
| 今天轮次 < `max_rounds_per_day` | 成本闸门 |
| 最近 `active_within_minutes` 分钟内有对话 | 安静太久就没料可想 |
| **该会话有新的真人消息**（输入水位） | 见下 |

**输入水位**这一条是实盘踩出来的：原来每 5 分钟重新发散一次，群安静、消息还是那几条，模型手上没新数据，只能把同一句思绪换个说法交上来——连续 6 轮全是「同一件事情」的变体；
看起来像在思考，其实在原地踏步


所以 `chain.last_input_ts` 记下这一轮消费到哪条消息，下一轮没有新消息就跳过。
**水位必须排除自己说的话**（用 `LastOtherMessageTs`），否则它自己刚说完一句就触发下一轮，
自己把自己催着继续想。

手动触发（后台「立刻想一次」）不走这道闸。

## ② 意图判定：决定"要不要开口"

`IntentAgent` 读**真实上下文**（最近 14 条对话原文 + 在场的人 + 记忆 + 在意的事 + 上次卡在哪），
输出：

```json
{
 "intent": "none|answer|ask|care|share|correct",
  "about": "要回应的那件具体的事，≤20字",
  "why": "我为什么该开口",
  "confidence": 0-100,
  "not_yet": "现在还不该开口的理由" 
}
```

prompt 里把 `none` 定成**默认答案**，并明确列出哪些算"没有"：
插进去只是打断、不知道答案硬猜会编、只是想刷存在感、上一轮已经说过同样的话。

> **关键设计：没动机时不会终止整轮。
> 没动机时跳过「上下文」那一路（没东西可回应，硬凑只会产"硬找话说"的念头）**，但仍然跑「记忆碎片」那一路，收敛时把 `act` 明确禁掉（提示词说一遍 + 代码再硬拦一次），这一轮照样能产出「加权意向」。

意图判定本身失败（网络/解析）时立刻收尾——不再白烧后面两次调用。

---

## ③ 双路发散：为什么必须分开跑

| 节点 | 只看 | 回答 | 典型形态 |
|---|---|---|---|
| **上下文** | 自我 + 现在 + 最近对话 + 群体语境 + 意图锚 | 对方想让我做什么 | 「记得主动和我说话」 |
| **记忆碎片** | 在意的事 + 记忆碎片 + 画像 + 上一版思绪 + 卡住提醒 | 我自己在意什么 | 「她之前问过我的梦想是什么」 |

**两路互斥是刻意的**：带了对方的话就变回"回应"，带了自己的事就会跑题。

实测「群里在聊接模型接入、心跳保活，它在想她喊困」。拆成两路之后，跑题的那一路会被另一路抵消掉。

两路各写 `max_thoughts / 2` 条，合并成 `round.Thoughts`。

---

## ④ 合成思想

两路念头直接拼接。后台「最近几轮」的四段卡片里，第一段会显示**分层输入**
（自我 / 最近信息 / 记忆碎片 / 画像 / 在意的事 / 上次思绪），第二段显示这一版冒出的念头。

采集（`CaptureInputs`）和拼接（`BuildUserContext` / `BuildSelfContext`）用的是**同一份数据**，
不会出现"后台看到的输入"和"模型真正看到的输入"不一致

---

## ⑤ 收敛：双输出

```json
{
 "reply": "那句答复，≤40字",
  "topic": "落在哪件具体的事上，≤8字",
  "why": "≤20字",
  "intent": 
   {
       "kind": "none|weight|act",
       "target": "group:<群号> / private:<QQ号>",
       "who": "对方名字",
       "text": "kind=act 时要发出去的原话",
       "body": "kind=weight 时：我要和谁做什么、为什么",
       "reason": "≤20字" 
   } 
}
```

**三档，默认是第一档：**

1. `none` —— 什么都不做。思绪只是思绪，说完就在心里放下了。
2. `weight` —— 加权重。现在不做，但这件事值得我以后更在意。
3. `act` —— 真的做一件事，转成提案走准入闸。

`topic` 是**归并标签**，专门用来判断"是不是又在想同一件事"，见下。

---

## ⑥ 加权归并：为什么权重必须累加得起来

收敛产出的"加权意向"不是一句话，而是结构化的两段：

```
title: 在群里发言 / 和星涵私聊     ← 由 (kind, target) 推出来，不让模型自由发挥
body : 我要和谁做什么、为什么
```

累加键是 `(kind, target)`。

**为什么不能用自由文本 + 字符串相似度**：实盘里权重列表长这样——

```
她说困时多接一句，别急着劝睡（1.00）
下次想接话时别等，先蹬那两脚（0.20）
下次答这类事别只给干条，带点活人语气（0.20）
升级后留意自己说话和接话有没有变样（0.20）
升级前先把自己现在的状态和聊到的事记一下（0.20）
```

五条并列的 0.20，谁也不比谁重，因为它们其实分属不同的落点、混在一个列表里永远合并不掉。

而且**整句相似度抓不住"同一件事"**：
「她喊困却没走，我别急着追问…」和「她那句困可能是想有人陪…」的字符二元组交集是 **0**，
但显然是同一件事。所以归并要比**主题标签**，不比句子。

**加权子 AI**（`WeightAgent`）负责归并：每次新意向进来，把它和**当前所有未执行**的意向
一起交给模型，做一次整理——同一落点的权重相加（上限 1.0），表述重合的合并，
`body` 取更能指导行动的那句。模型挂了退回朴素合并（同键相加），不丢数据。

所以 `0.2 + 0.2 + 0.2` 会真的变成 `0.6`，而不是三条并列的 `0.2`。

## ⑦ 准入 + 落定：七道闸

`act` 这一档要过七道闸，每一道都记进 `data/idea/ledger.jsonl`：

| # | 闸 | 拦下时记的 `blocked_by` |
|---|---|---|
| 1 | 总开关 | `disabled` |
| 2 | 意图白名单 | `intent` |
| 3 | 静默时段（硬禁） | `quiet` |
| 4 | 目标是否可被打扰（在线状态） | `presence` |
| 5 | 同一对象冷却 | `cooldown` |
| 6 | 每小时上限 | `hourly` |
| 7 | 每日上限 | `daily` |

> **在线人只算"可私聊的人"**。群里说过话但没加好友的号，私聊根本发不出去；
> 把他们当目标，结果就是白想一轮、执行必然失败。

落定有六种结局，都会出现在后台四段卡片的第 4 段：
`sent`（说出口了）/ `blocked`（被拦）/ `no_intent`（没动机）/ `no_idea`（没念头）/
`weight_only`（只加了权重）/ `error`。

## 思想链：让念头自己滚起来

每个对象一条链（`data/idea/chain/<target>.json`）：

```
v1：吃完整材料想到的
v2：材料 + v1 想到的
v3：只剩 v1 的思绪，材料不再重复喂
...
到 max_versions 就重置，重新吃一次完整材料
```

*Tip**喂同一份材料那样每次都会得出同一个结论**
实测过连续几轮全是"发散后没有值得做的念头"*

**卡住检测**：`chain.topics` 存最近 6 个主题标签，连续 ≥2 轮同题时，下一轮的母题里插一段：

> 【你在同一个地方已经卡了 N 轮】连续 N 版都落在「X」上。这一版不能再说这件事——
> 换一个完全不同的角度：换个人、换个时间段、换个动作，或者干脆想点别的。

后台「最近几轮」的收敛段会标出「卡住了：连续 N 轮同题」。

## 关键参数（`config/idea.json`）

| 参数 | 默认 | 作用 |
|---|---|---|
| `interval_minutes` | 5 | 多久想一次 |
| `think.max_rounds_per_hour` | 6 | 每小时上限（成本闸） |
| `think.max_rounds_per_day` | 40 | 每天上限 |
| `think.active_within_minutes` | 60 | 最近这么久有对话才想 |
| `think.max_targets_per_round` | 2 | 一轮想几个对象 |
| `chain.max_thoughts` | 4 | 一次最多几个念头（两路各一半） |
| `chain.window_messages` | 12 | 上下文那一路看多少条 |
| `chain.max_versions` | 8 | 链滚多少版后重置 |
| `intent.min_confidence` | 45 | 低于此视为"没动机" |
| `per_target_cooldown_hours` | 1 | 同一对象冷却 |
| `quiet_hours` / `allow_window` | 01:00-08:00 / 10:00-20:00 | 静默 / 允许时段 |

## 怎么判断它坏了

| 现象 | 先看哪里 |
|---|---|
| 后台「思想」一直是 0 次 | span 有没有写（`data/audit/spans/<日期>.jsonl` 里搜 `"neuron":"idea"`） |
| 一直 `no_intent` | 意图子 AI 的 `not_yet` 文本；`intent.min_confidence` 是否过高 |
| 一直想同一件事 | 后台收敛段的「卡住了」标记；`chain.topics` |
| 权重不涨 | 后台「加权意向」页；`idea/weights.json` 里是不是每条 `target` 都不同 |
| 一轮要很久 | 后台「耗时瀑布」看是哪一段慢 |
| 想出来了但没发 | `idea/ledger.jsonl` 的 `blocked_by` 字段 |

## 页面速览（后台 `#idea`）

从上到下：**运行状态 → 思想拓扑 → 耗时瀑布 → 加权意向 → 在线状态 → 配额 → 最近几轮 → 准入记账**。

- **思想拓扑**：把最近一轮的完整决策链画出来，出问题第一眼看这里
- **耗时瀑布**：五段各花多少毫秒
- **四段卡片**：每轮一张，分「发散 / 收敛 / 决策 / 落定」，收起时只有一行

## 补充：该层可能的一个异常

该结构可能会出现的几种异常Bug，因为该项目涉及到 自学习与AI，这会导致bug几乎无法复现和短期内浮现，而且修复难度较大
有可能突然就好了也有可能突然就出现，开发者的该AI仅学习至5天，所以不确定是否后续仍会触发此问题

### 1.心结
特征：即AI反复思考同一个问题，经过反复提升权重后仍因为各种情况导致无法执行
这个问题一般原因是AI反复纠结'这个问题我还没考虑好'、'我做不到'、'我担心这会影响你'等偏内向自卑或等待他人外部引导的因素
越想越想，但是一直无法说出口


### 2.重复发散
特征：即AI反复聊到了同一件事复读，AI对同一个问题不断变换表述方式重复回答，看似在补充，实则没有新增信息量
这个问题一般原因是出自于③ 读碎片 → ⑤ 产出问题这一步，你回答后AI仍会将这一块被回答过的碎片当作思绪问题；
