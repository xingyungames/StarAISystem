# ⑩ 可观测性

> 代码：`src/StarGameAI/Core/Tracer.cs`、`Memory/DeltaLog.cs`
> 数据：`data/audit/`
> 页面：后台 `#trace`（神经活动）、`#delta`（变化度）、`#logs`（日志）

一句话：**没有任何一层是靠"感觉调好的"。所有判断都必须能在后台看见、能被数据复算。**

---

## 一份 span，一条 trace

每条进来的消息是一个 **trace**，它在管线里经过的每个阶段各记一个 **span**：

```
gate     发言门判定
recall   记忆检索
speak    模型生成（含追加）
tool     工具调用
send     发送
idea     思想层每轮一条（独立 trace）
```

span 长这样：

```json
{ "trace_id": "t_738e930c85d2", "seq": 1, "neuron": "recall",
  "ts": 1793086998, "ms": 110, "ok": true, "stage": "recall",
  "in_chars": 0, "out_chars": 717, "tokens": 0,
  "brief": "历史0条 记忆717字 系统1452字" }
```

### 三条约定

| 约定 | 为什么 |
|---|---|
| **只记长度与摘要，不记聊天正文** | 审计目录不该成为第二份聊天记录 |
| **静默也必须留痕** | 否则可视化里会出现"这条消息凭空消失"的断流 |
| 按天滚动，保留 N 天 | `span_retention_days`，启动时自动清理 |

---

## 两份审计的区别

| 文件 | 内容 | 用途 |
|---|---|---|
| `audit/spans/<日期>.jsonl` | 神经元级埋点 | 瀑布图、耗时分析、拓扑 |
| `audit/gate.jsonl` | 发言门每次判定的完整结果 | 调阈值、复盘误判 |
| `audit/dialogue.jsonl` | 分块判定（含候选打分） | 分块器验收 |
| `audit/delta.jsonl` | 人设/画像改写的前后相似度 | 变化度 |
| `audit/send.jsonl` | 每次发送 | 排障 |
| `audit/admin.jsonl` | 后台改配置的动作 | 谁在什么时候改了什么 |
| `idea/ledger.jsonl` | 思想提案与七道闸结果 | 为什么没发出去 |

**span 是索引，具体审计是细节。** 排障时先看 span 找出是哪一段慢/失败，
再去看对应审计的具体内容。

## 后台三个页面

### `#trace` 神经活动

上半是**神经元拓扑**（今日汇总）：每个神经元今天被调用了多少次、平均耗时、
成功失败比。下半是**消息瀑布**：选一条 trace，看它在这条管线里每段花了多久。

这是回答"它今天都干了什么"最直接的地方。

### `#delta` 变化度

**这里没有 loss。** LLM 是推理时系统，没有梯度、没有参数更新，算不出 loss。

给的是可观测的代理量：

```
变化率 = 1 - 相似度（改写前后文本的字符二元组 Jaccard）
```

它只回答一个问题：**自我被改写了多少。** 每日柱状图能看出人格是在慢慢漂移，
还是被某次巩固推得跳变。

### `#logs` 日志

按日期 / scope / trace 浏览缓存日志，行展开看完整 JSON，可按需加载发言门审计。

## 指标（`/api/neurons/stats`）

| 字段 | 含义 |
|---|---|
| `calls` | 今日调用次数 |
| `ok` / `fail` | 成功 / 失败 |
| `avg_ms` / `max_ms` | 平均 / 最大耗时 |
| `tokens` | 该神经元消耗的 token |
| `gate_stages` | 发言门各阶段的命中分布（规则/模型/冷却/额度…） |

**「思想」长期为 0 次**曾经是一个真实故障：`IdeaEngine` 注入了 `_tracer` 但从来没用过，
一个 span 都不写。报表按 span 聚合，所以跑没跑都显示 0。

> 观测缺失和功能失效在报表上一模一样。这条必须补，不能靠"我记得它能跑"。

## 排障顺序

遇到"它今天有点怪"：

```
① 后台「仪表盘」       NapCat 在不在线、最近一次巩固成功没
② 后台「神经活动」     今天各神经元调用量与耗时，找出异常的那一段
③ 对应页面的沙盒       发言门 / 分块都能"粘一段话试判"，不用发真消息
④ 具体审计文件         gate.jsonl / dialogue.jsonl / idea/ledger.jsonl
⑤ 对应层的文档         看那一段的设计意图是什么（docs/layers/）
```

## 保留策略

| 数据 | 默认保留 |
|---|---|
| span | 7 天（启动时清理） |
| gate / dialogue / delta / send / admin 审计 | 不自动清理 |
| 聊天日志 | 不自动清理 |
| 浅层碎片 | 7 天，过期进 `archive/` |
| 分块未归属消息 | 24 小时 |
