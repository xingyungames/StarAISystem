# ⑨ 睡眠巩固

> 代码：`src/StarGameAI/Sleep/`（`SleepScheduler.cs` / `Consolidator.cs` / `SleepRunner.cs`）
> 配置：`config/sleep.json`
> 页面：后台 `#sleep`（睡眠）、`#delta`（变化度）

一句话：**这是整套系统里唯一能把"经历"变成"自我"的机制。**

对话过程中的一切即时反应都不改写人设；只有这里能。这是核心命题的直接实现：

> harness 只保证一段不可变的 bootstrap，其余一切必须经过「睡眠-巩固」才能获得权威性。

---

## 什么时候睡

四条触发，任一满足即可，但都必须先过「空闲」与「最小间隔」：

| 触发 | 条件 |
|---|---|
| 睡眠信号 | AI 在对话里调 `request_sleep` 登记的意愿 |
| 当日日志量 | 当天记录条数 ≥ `log_threshold_entries` |
| 作息窗口 | 落在 `windows` 时段内 |
| 距上次成功太久 | ≥ `max_hours_between`（防止长期不巩固，记忆只增不减） |

另有首次兜底：从未成功巩固过、且已经有待处理日志 → 立刻做一次。

**空闲要求**：对话进行中不睡（`idle_required_seconds` 内有人说话就延后）。

**失败退避**：连续失败不会每 60 秒重试，而是拉开到 15 分钟。

## 分五段

```
① 取料    水位线之后的全部日志（今天 + 昨天两个目录，覆盖跨天）
② 分片    按条数/字数切块，带重叠
③ 蒸馏    每片调一次模型 → 候选条目（含类型、标签、权重、置信度）
④ 归并    精确匹配 + 近似匹配，保留置信度更高的
⑤ 提交    碎片入库 / identity 并进人设 / 收敛结果重写画像
```

### ① 水位线

`data/sleep/watermark.json` 记 `LastConsumedLogTs`。只处理这之后的新记录。

> **任何分片失败都不推进水位线。**
>
> 否则那批对话会被永久跳过——静默丢失记忆，最难发现的一种 bug。
> 下次重跑靠"已存在条目去重"保证幂等，不会重复写入。

### ② 分片

按 `chunk.max_entries` / `max_chars` 切，块之间留 `overlap_entries` 条重叠，
避免一句话被切在边界上。一次巩固最多处理 `max_chunks_per_run` 片。

### ③ 蒸馏

每片一次调用，产出候选：

```json
[ { "kind": "identity|fact|preference|event|capability_gap|commitment",
    "text": "≤60字",
    "tags": ["≤3个"],
    "weight": 0-100, "confidence": 0-1,
    "strictness": "hard|soft",       // 只有 commitment
    "validIn": ["..."],              // 只有 commitment
    "evidence": ["消息序号"] } ]
```

prompt 里有几条是花时间换来的规矩：

| 规矩 | 为什么 |
|---|---|
| 「宁可少记一条事实，也不要漏记一条约束」 | 实测记了 44 条「对方叫星涵」的变体，真正重要的约定一条没记 |
| 「明显的事实不要反复记」 | 同上，把记忆撑满、把约束挤掉 |
| 「一次性的临时让步不要写成习惯」 | 「这次算了」不是「以后都可以」 |
| 「带条件的话优先抽成 commitment」 | 如果…就…、只…才…、别…、不许…、下次… |

### ④ 归并

同一片内、跨片之间都做归并：类型相同且文本相同/近似 → 保留置信度更高的那条。

### ⑤ 提交：三个去处

```
identity 候选  → 并进人设【身份】段（整段重写，不是追加）
fact/preference/event/commitment → 浅层碎片入库
所有碎片       → 触发画像重写（人物 / 群），被用到的碎片打 absorbed
```

**人设是整段重写，不是追加。** 追加会不可控地膨胀、且新旧句子会自相矛盾。
重写保证条数恒定、每句都是当下成立的。

## 人设改写与变化度

人设是 `data/persona/System Prompt.md`，用锚点分段：

```markdown
<!--seg:identity-->
我是谁
<!--/seg:identity-->

<!--seg:style-->
说话风格
<!--/seg:style-->
```

每次改写都记一条 `data/audit/delta.jsonl`：

```json
{ "ts": ..., "target": "persona/identity", "similarity": 0.87 }
```

**`变化率 = 1 - similarity`。注意这不是 loss。**

LLM 是推理时系统，没有梯度、没有参数更新，算不出 loss。
这个数是可观测的**代理量**，只回答一个问题："自我被改写了多少"。

后台「变化度」页把它画成每日柱状图，可以看人格是在慢慢漂移还是被某次改写推得跳变。

---

## 为什么巩固只写、不删

碎片过期会被搬到 `archive/`（不物理删除），画像被整段重写时**旧内容进 persona 快照**。

这是为了可回溯：人格变了之后，要能查出"是哪次改写、基于哪些碎片"。

## 配置（`config/sleep.json`）

| 参数 | 作用 |
|---|---|
| `enabled` | 总开关 |
| `windows` | 作息窗口（可跨午夜） |
| `interval.min_hours_between` / `max_hours_between` | 最小间隔 / 强制兜底 |
| `idle_required_seconds` | 多久没人说话才算空闲 |
| `log_threshold_entries` | 当日日志量触发 |
| `behavior_while_sleeping` | `silent` / `fast_reply` / `queue` |
| `chunk.*` | 分片条数、字数、重叠、单次最多片数 |

`behavior_while_sleeping` 建议 `fast_reply`：照常回复，只是记忆注入降级为瘦身版。
`silent` 会让巩固期间完全不说话（用户会觉得"它死了"）。

## 后台怎么用

「睡眠」页能做：改作息、手动触发一次巩固、看睡眠信号、看水位线。

手动触发适合**改完人设 prompt 或改完蒸馏 prompt 之后**立刻验证效果。

「变化度」页看人格漂移。

---

## 常见故障

| 现象 | 原因 |
|---|---|
| 记忆不更新 | 巩固一直失败（看后台 `last_error`） |
| 人设突然变了 | 「变化度」页看那天的改写量；`persona/history/` 有快照可回滚 |
| 记忆丢了一段 | 水位线被错误推进（旧版本的 bug，现已修） |
| 巩固很慢 | `max_chunks_per_run` 太大，或分片字数太小导致片数过多 |
| 群里说话它不记得 | 巩固没跑过 / 该 scope 没产生碎片 |
