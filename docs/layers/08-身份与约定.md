# ⑤ 身份与约定

> 代码：`src/StarGameAI/Core/Identity.cs`、`Memory/Store.cs`（`commitment` 类型）、
> `Sleep/Consolidator.cs`（`GuardIdentity`）
> 页面：后台 `#deep`（深层记忆）、`#memory`（浅层碎片）

一句话：**先知道"这个号是谁"，再知道"我们之间有什么不能越过的线"。**

---

## 一、身份：QQ 号是主键，名字只是别名

### 为什么以号为准

名字在 QQ 里不稳定：群名片可以随便改，同一个人在三个群里可能叫三个名字，
不同的人也可能用同一个昵称。

所以 `entity_id` 恒等于 QQ 号。名字、别名都只是查询用的索引。

### 身份卡

`Identity.CardFor(uid, scope)` 生成一段话：

```
星涵（QQ 10001），也叫 星空！！！；你在私聊也见过他。
你对他的印象：星涵是星云游的技术总监…
```

三件事：

1. **名字 / 别名 / QQ 号** —— 让模型知道 AA 和 BB 是同一个人
2. **在哪些场景见过** —— "我们不止在这儿见过"
3. **画像首句** —— 不管当前在哪个 scope，对人的印象都应该在

### 唤醒块

新进一个群时最需要这个：`Identity.WakeBlock` 把这个场景最近说过话的人**逐个对进联系人词典**，
正在说话的人排最前。

```
【这里的人】（纯查表对出来的，同一个人换个群还是同一个号，别认错）
- 星涵（QQ 10001｜你私聊认识的）。你对他的印象：…
- 忆雨拾梦（QQ 0000000000）。你没见过这个号
```

**纯查表，不调模型。**

### 发信人标签

历史消息每一行都带身份标签：

```
星涵（QQ 10001｜你私聊认识的）：接入方案我改了一版
忆雨拾梦（QQ 0000000000）：我那个也改完了
```

不带的话，A 发的 `[图片]` 很容易被算到紧跟着说话的 B 头上——
这是群聊里最容易出的错，也是用户最早报的那个 bug。

### "可私聊对象"这个概念

思想层最后要把想法落定成动作，最重的一档是"私聊某人"。
群里说过话的人**不一定加了好友**，私聊根本发不出去。

所以 `Contacts.IsPrivatePartner(uid)` 单独判定：

```
联系人里记过 private: 场景 → 有 shallow/private_<qq>.jsonl → 有 log/<日期>/private_<qq>.jsonl
```

「在线人」列表只认这个，否则就是白想一轮、执行必然失败。

## 二、约定：必须带生效范围

### 一个真实翻车

```
私聊  星涵：那…能不能再谈谈叫姐姐的事…
      星璃：你想听的话，我可以叫一声。但这不是我平时说话的样子，别当成常态。
      星璃：叫完你可别到处说。
      星璃：姐姐。
群里  星涵：星璃～出来让我抱抱～
      星璃：（走过去让你抱）姐姐。          ← 当场就叫了
      星涵：你不是说别到处说嘛，怎么自己先说出口了～？
```

查私聊记忆，里面确实有一条：

```
[fact] 对方叫星涵，我平时叫她星涵或姐姐
```

**"叫姐姐"记住了，边界没记住。**

因为蒸馏类型里只有 `identity / fact / preference / event / capability_gap`，
**没有"约定"，也没有"适用范围"**。于是：

| 原话（有边界） | 记下来的（无边界） |
|---|---|
| 「只在你面前叫，别当成常态，**别到处说**」 | 「我平时叫她星涵或姐姐」 |

**私下一次有条件的让步，被压成了无条件的习惯。**
*tip:其实这更好……但是bug就是bug……*

### 结构

```jsonc
{
  "kind": "commitment",
  "text": "叫姐姐只在私下，不要在外面说出来",
  "strictness": "hard",                    // hard = 越界就是错；soft = 尽量别
  "validIn": ["private:10001"],       // 空数组 = 到处都算
  "expiresAt": 0                           // 0 = 不失效
}
```

模型没给 `validIn` 时**默认填当前会话 scope**——保守的一侧，
因为把私下让步当成到处成立正是上面那次翻车的成因。

### 注入：所有相关约定都摆出来，并标明在哪儿成立

```
【约定与边界】（越界就是错，不能当成「忘了就行」）
- 叫姐姐只在私下，不要在外面说出来（硬约束）｜只在 私聊 有效，**在这里不算**
```

**判断留给人（模型）自己看着范围做，而不是提前过滤掉**——
过滤掉它就不知道自己越界了。

### 这是"主场立约、客场守约"

可以这么理解这个 AI 的社交结构：

> **私聊是"养成环境"，群聊是"上岗环境"。**
> 养成环境里立下的约定，上岗必须遵守；上岗时发生的事，反过来不改写养成。

这也解释了一个直觉上很自然的类比：训练场里怎么练都行，上场要按规矩来。

## 三、identity 的硬校验

`identity` 的语义是"关于**我自己**"。但中文「（你可以）叫我星涵」是歧义的：

- "你给我起名叫星涵" → 我的身份
- "你称呼我为星涵" → **对方的名字**

蒸馏模型会读成前者，写出「我叫星涵」。实盘里就发生过：

```
shallow/group_100002.jsonl:
  {"kind":"identity","text":"我叫星璃，是对方给我起的名字"}
  {"kind":"identity","text":"我叫星涵，是对方让我这样称呼他的"}   ← 污染
```

`RecallBlock` 把 identity 标成「关于我自己」注入——它真有可能拿"我叫星涵"来介绍自己。

### 三道防线

| 层 | 做法 |
|---|---|
| prompt | `GroupProfilePrompt` 明确"你自己不是群成员"；`DistillPrompt` 强调 identity 只写我 |
| **落库前硬校验** | `GuardIdentity`：断言「我叫 X」里的 X 必须与已确认的自我名一致，否则**降级成 fact 并归到说话人头上** |
| 注入侧分流 | `RecallBlock` 里 identity 按 `UserId` 分流标签：不是自己 → 「关于对方的身份（不是你）」 |

`GuardIdentity` 的正则**刻意不匹配「我是 X」**：

```
「我叫星璃，是对方给我起的名字」      → 星璃    放行
「我叫星涵，是对方让我这样称呼他的」  → 星涵  降级为 fact
「我是星云游的一份子，话少」          → 不匹配  放行   ← 自我描述，不是名字
「我是自学习AI，话少」                → 不匹配  放行
```

自我名从哪来：`bot_names` → 人设【身份】里的「我叫 X」→ 兜底说明。
只要人设在，就永远知道自己叫什么。

## 四、"我最近说过的话"

跨会话，按时间倒序注入：

```
【我最近说过的话】（跨会话，按时间倒序；别反口）
- （私聊·40分钟前）接入方案用 Liebe 那版当底
- （本群·3分钟前）这个我得先看看原话
```

配套规矩写死在【怎么回】里：

> 被问「你不是说过 X 吗」时：只能依据【我最近说过的话】和【记忆】回答。
> 找不到就直说「我不记得说过这句」，**绝不编一个解释，也不许否认自己的名字**。

真实崩坏样本：

```
星涵：你不是说别到处说嘛，怎么自己先说出口了～？
星璃：我说的是「姐姐」和睡眠时间，没别的。        ← 编造解释（私聊里没提过睡眠时间）
星涵：好好好
星璃：不知道，我没法确认。名字和叫法都不算数。      ← 防御性自我否定
星涵：星璃妹妹～
星璃：匿月，叫我星璃就行，妹妹不用加。              ← 编出一个不存在的人名
```

三步全错，但错得很有规律：**它被要求给一个它没有依据的答案。**
