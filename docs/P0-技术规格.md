# StarGameAI · P0 技术规格

> 自构 AI（内核不变量 + 可写自我）的 C# 服务端。
> 传输层：NapCat OneBot 11（实测 `get_status` retcode 0 / online true）。
> 模型层：DeepSeek（`deepseek-flash`，OpenAI 兼容 `/chat/completions`）。
> 工具层：Python 子进程（沙箱执行、自动准入、可禁用）。
> 后台：静态 HTML + 原生 JS，蓝色主题，无 emoji，由本服务托管。

本文档是**实现依据**，不含代码。所有条目都是可验收的。

---

## 0. 范围与不变量

P0 交付闭环：**收到 QQ 群/私聊消息 → 缓存日志落盘 → 发言门判定 → 记忆注入 → DeepSeek 生成 → NapCat 发送**，外加可手动触发的**分片睡眠巩固**和**只读优先的管理后台骨架**。

架构不变量（越往后越不能破，评审时逐条对照）：

| # | 不变量 |
|---|---|
| I1 | 基础 System Prompt 是服务端常量，模型永远不可写、不可见其"提示词"本体 |
| I2 | 子 AI 输出必有 token 上限，不接受自由文本回传主上下文 |
| I3 | 每个子 AI 一份最小能力矩阵，写权限互不重叠 |
| I4 | 自我一日一醒：`System Prompt.md` 每天最多被读一次、最多被改一次 |
| I5 | 白天只写缓存日志，不写自我 |
| I6 | 睡眠分四段（分流 → 巩固/合成 → 校验 → 提交），仅"提交"碰持久数据，且事务化 |
| I7 | 新 Python 工具必须过契约 + 静态检查 + 自动试跑，任一不过即 `disabled`；通过则自动 `active`（`auto_approve:false` 时可切回人工批准） |
| I8 | 删除 = 打 tombstone；承诺/偏好/禁忌/身份为 pinned，任何路径不可物理删 |
| I9 | 每次睡眠产出 diff 快照，可回滚 |
| I10 | 发言门的"沉默"必须留日志，可统计漏言率 |
| I11 | 日志层在消息入口写入，零模型调用，永不因下游失败而丢 |
| I12 | 工作集是缓存，不落盘，可随时丢弃重建 |
| I13 | 巩固以**水位线**驱动，不以日期驱动 |

## 3. 数据与文件格式

### 3.1 缓存日志（I11）

`data/log/<yyyy-MM-dd>/<scope>.jsonl`，一行一条，**网关入口同步写入，不等任何判断**。

```json
{"ts":1760000000,"message_id":"123","trace_id":"t_ab12","scope":"group:100001",
 "user_id":"10001","name":"星汐","role":"member","is_self":false,
 "text":"帮我查下几点","segments":[{"t":"text"},{"t":"image","brief":"[图片]"}]}
{"ts":1760000002,"message_id":"124","trace_id":"t_ab12","scope":"group:100001",
 "user_id":"10000","name":"星云游Office","is_self":true,
 "trigger":"reply","in_reply_to":"123","text":"现在是下午三点半。"}
```

- `scope`：`group:<群号>` / `private:<QQ号>`
- `segments` 只保留类型与摘要，不存二进制；图片/语音存 `brief` 与 `url`
- 入站来自 NapCat 上报，出站由 C# 发送成功后回写（§4.4）。**出站日志是 AI 话语的唯一来源**，因为 `reportSelfMessage=false`

### 3.2 记忆条目（单一真相）

`data/memory/entries/<scope>.jsonl`

```json
{"id":"k3f9a1","ts":1760000000,"scope":"group:100001","kind":"fact",
 "text":"小星在学 Python","tags":["课程"],
 "weight":63,"level":"private","pinned":false,"tombstone":false,
 "source":"chat:2026-10-25","confidence":0.6,"reinforced":1,
 "user_id":"U1","user_name":"小星"}
```

- `kind ∈ {identity, fact, preference, event, quote, capability}`
- `level ∈ {public, member, private}`
- `tombstone:true` 即为删除，检索与注入一律跳过，物理清理只由离线任务做
- `pinned:true` 的任何路径都不可删（I8）

### 3.3 用户画像（人可读）

`data/memory/profiles/<uid>.md`，正文人可读，顶部有一行机读锚点供网页解析成表格：

```markdown
<!--profile {"uid":"U1","names":["小星"],"likes":["美式"],"dislikes":[],"topics":["Python"],"turns":42,"updated_at":1760000000}-->
# 小星

## 已知
- 在学 Python

## 喜欢
- 美式
```

### 3.4 自我（`System Prompt.md`）

正文是 md，**用 HTML 注释切段**（C# 手写解析，零依赖）：

```markdown
<!--seg:identity-->
我是一个喜欢在后半夜说话的助手……
<!--/seg:identity-->

<!--seg:style-->
说话短，少用敬语。
<!--/seg:style-->
```

**分段权限（I1 + N5 防护）**

| 段 | AI 可写 | 后台可写 |
|---|---|---|
| `identity` | 是（受预算约束） | 是 |
| `style` | 是（受预算约束） | 是 |
| `interest` | 是（受预算约束） | 是 |
| `boundaries` | **否** | 是 |
| `output_rules` | **否** | 是 |

`meta/system-prompt.json`：

```json
{"rev":7,"updated_at":1760000000,"by":"sleep:merge","budget":{"limit_per_day":1,"used_today":0,"reset_on":"2026-10-26"},"segments_hash":{"identity":"a1b2","style":"c3d4"}}
```

未改动的段 hash 不变；只有 hash 变化的段才计入"改动"。

### 3.5 工具（Python）

`data/tools/<name>/`

- `tool.md` — 契约（AI 写、AI 读、后台展示）
- `main.py` — 实现
- `meta.json` — 状态机与校验记录

契约格式（`tool.md` 顶部锚点，机读）：

```markdown
<!--contract
{"name":"get_time","version":1,
 "description":"获取当前时间，可指定时区",
 "params":{"tz":{"type":"string","required":false,"default":"local"}},
 "returns":{"type":"string","desc":"ISO8601 时间字符串"},
 "side_effects":"none",
 "timeout_s":5}
-->
# get_time

返回当前时间。失败时返回空字符串并在 stderr 说明。
```

状态机：`draft`（合成中）→ 门禁通过 → `active`（进工具列表）→ `disabled`。`auto_approve:false` 时 `draft` 与 `active` 之间多一个 `pending`（待批准）。**仅 `active` 出现在模型工具清单里**（I7）。

## 4. 网关

### 4.1 接收

- 端点：`POST http://127.0.0.1:11221/`（NapCat 配置的 `httpClients.url` 已指向 `:11221`）
- 校验：**NapCat 不发 `Authorization`**，它带的是
  `x-signature: sha1=<hex>`，其中 `<hex> = HMAC-SHA1(key = report.token, data = 原始 body 字节)`，
  外加 `x-self-id: <机器人QQ>`。必须对**原始字节**做 HMAC（不能先解码成字符串再编码）。
  另保留 `Authorization: Bearer <report.token>` 作为手工调试通道。不匹配 → `401` 并记日志。
- Body：**裸 OneBot 11 事件**（无外层包装），`messagePostFormat=array`
- **立即返回 200 且响应体为空**——NapCat 会把响应体当「快速操作」解析，返回 JSON 会被它继续消费。

处理顺序（均在队列消费者里）：

1. `post_type != "message"` → 落 `audit` 后丢弃（P0 不处理 notice/request）
2. `user_id == self_id (10000)` → 丢弃
3. `message_id` 去重（`Dedup`，LRU 5000 / TTL 30min）→ 命中则丢弃
4. **写缓存日志**（I11）
5. 入管线（§5）

### 4.2 会话与触发

- `message_type=private` → `scope=private:<user_id>`
- `message_type=group` → `scope=group:<group_id>`
- 群消息在 NapCat 下**全量可见**（这是选 NapCat 的核心收益），不要求 @；是否回复由发言门决定
- 白名单：`config/server.json` 增 `whitelist.groups` / `whitelist.private`；未命中按 `unknown_action: silent`

### 4.3 发送

- `POST {napcat.api_base}/send_group_msg` / `/send_private_msg`，`Authorization: Bearer {napcat.api_token}`
- 分段：单条 ≤ `reply_max_chars`，超长按段落切分，最多 3 段
- 限速：`SemaphoreSlim` per scope，`per_group_per_second=1`；被限速时排队而非丢弃
- 失败：`retcode != 0` 或 5xx → 重试 2 次（退避 1s/3s），最终失败只记日志、不重发（避免刷屏）
- 高风险：本账号是**个人 QQ 号**，限速与日预算是唯一护栏，不做"补发"

### 4.4 外发回写

日志由两侧合成，**不缺 AI 发言**：

```
用户输入  ← NapCat 上报   → 写日志（is_self:false）
AI  输出  ← C# 发送后回写 → 写日志（is_self:true）
```

因为 `httpClients.reportSelfMessage=false`，出站方向必须由 C# 自己补齐。注意这条不是"补漏"，而是**出站日志的唯一来源**，所以有三条纪律：

| 纪律 | 内容 | 不遵守的后果 |
|---|---|---|
| **只写成功** | 仅在 `retcode==0` 且拿到真实 `message_id` 后才写日志 | 否则 AI 会"记得自己说过一句其实没发出去的话"，被写进事件记忆 |
| **失败单独记** | 发送失败只进 `audit/send.jsonl`，**不进 chat log** | 同上；且失败原因需要独立统计 |
| **主动发言也要写** | 门控主动插话、睡眠后的"回过神"补充、定时问候——这些**没有对应用户输入**，必须独立写入并标注 `trigger` | 否则日志里出现"AI 说了一句但没有触发记录"，巩固时无法还原因果 |

日志记录增补两个字段：

```json
{"is_self":true,"trigger":"reply|ambient|recall|manual","in_reply_to":"<用户 message_id, 可为空>"}
```

**幂等**：`is_self` 记录与入站记录**共用同一份 `Dedup` 表和同一套 `message_id`**（都用 NapCat 返回的真实 id）。这样万一将来把 `reportSelfMessage` 打开用于排查，同一条发言不会从两条路径各记一次。

## 5. 消息管线

```
[入口·零模型]  去重 → 写日志（已完成于网关）
      ↓
[门控] 规则层 → 概率抽样 → 意愿打分（一次小请求，返回 {speak, score, need_think})
      │  判"不发言" → 结束（主上下文零增长，但日志已落盘 + 记漏言审计）
      ↓
[注入] 工作集命中？命中 → 直接注入（0 次子 AI 调用）
      │            未命中 → 同步检索（档位：快/标准/深度，见下） + 触发异步预取
      ↓
[生成] need_think ? 思想神经元(thinking=enabled) : 直接发言神经元
      ↓
[工具] 模型请求工具 → Runner 执行 → 回灌 → 循环（≤ max_tool_steps）
      ↓
[发送] NapCat → 回写日志
```

### 5.1 三档延迟预算

| 档 | 触发条件 | 串行模型调用 | 目标延迟 |
|---|---|---|---|
| 快 | 工作集命中 且 无工具 且 短消息 | 1（门控自带） | < 4s |
| 标准 | 工作集未命中 或 需要一次检索 | 2 | < 8s |
| 深度 | `need_think=true` 或 显式要求 | 3~5 | < 25s |

门控在返回 `speak` 的同时**顺手输出 `need_think`**（它已经在读上下文，这个位是免费的），不要为"要不要深度思考"再单独调一次模型。

### 5.2 发言门（移植 `ambient.py` 的判定，丢弃平台额度）

分层（顺序即成本顺序）：

1. **硬规则（0 成本）**：被 @ / 命中前缀（`#ai`）/ 私聊白名单 → `score=100`，`speak=true`
2. **噪声过滤（0 成本）**：纯灌水/表情/单字 → `speak=false`
3. **风控（0 成本）**：冷却未过 / 今日主动额度已满 → `speak=false`
4. **抽样**（`sample_rate=0.4`）→ 未命中即静默
5. **意愿打分**（1 次小请求）：输出 `{"score":0-100,"reason":"≤20字","intent":"answer|add|ignore","need_think":bool}`
6. **阈值**：`addressed` 用 `direct_threshold=45`，旁听用 `ambient_threshold=60`

与 qqbot 的差异：**删掉** `allow_active_outside_window`、`window_seconds`（那是 botpy 的 5 分钟被动回复窗口）；**保留** `cooldown_seconds=90`、`daily_budget`、`max_llm_calls_per_day`（现在是抗风控而不是抗平台额度）。

**新增**：所有 `speak=false` 必须记 `data/audit/gate.jsonl`，字段含 `trace_id / score / why_not / used_llm`。后台出"漏言率"曲线（人工抽样判定"本该回却没回"）。

### 5.3 注意力管理器（I12）

- 工作集：`ConcurrentDictionary<string, Card>`，会话内有效，**不落盘**
- `Card = { durable 摘要, 今日尾部摘要, 依据, fetched_at, stale }`
- 触发预取的四种信号：新参与者进入 / 话题偏移超阈值 / 某人被高频提及（滑窗计数）/ 门控判定发言但工作集缺此人
- 卡片字段必须含 `just_recalled:true` 与 `依据`（来源 + 时间），让生成层用"我刚想起来"的措辞，而不是当成新断言
- 配额：每会话预取 ≤ 20 次、每次 ≤ 6 人、注入 ≤ 900 字符；超限即止
- 取消：话题离开 / 会话结束 / 配额耗尽 → 取消在途任务

### 5.4 记忆注入与排序

排序单位是**条目**，不是文件：

```
score = 0.50 × 关键词覆盖度（字符二元组，中文不用分词）
      + 0.20 × 话题权重（当前滑窗高频实体，复读会自然抬高）
      + 0.15 × 权重/100
      + 0.10 × 时间衰减（半衰期 30 天）
      + 0.05 × 类型加成（identity 1.0 / fact 1.0 / preference 0.9 / event 0.8 / quote 0.5 / capability 0.7）
```

- **先过滤再打分**：`level` 可见性（`private` 仅本人与 owner）+ `tombstone=false`
- 预算：`context_max_entries=5`、`context_budget_chars=1200`、`min_score=0.18`

## 6. 睡眠子系统

### 6.1 触发仲裁（三源）

| 源 | 载体 | 说明 |
|---|---|---|
| 作息 | `config/sleep.json` | **AI 可自由编辑**，后台可覆盖 |
| 睡眠信号 | `data/sleep/signals.jsonl` | AI 在对话中调用内置工具 `request_sleep(reason)` 发出"我想找时间更新"的意愿 |
| 手动 | 后台 | 立即或排队 |

`config/sleep.json`

```json
{
  "enabled": true,
  "ai_editable": true,
  "windows": [{ "start": "02:30", "end": "05:30" }],
  "interval": { "min_hours_between": 8, "max_hours_between": 24 },
  "idle_required_seconds": 180,
  "defer_if_busy": true,
  "log_threshold_entries": 800,
  "behavior_while_sleeping": "silent"
}
```

仲裁逻辑：

- **必须满足**：`idle_required_seconds` 内无在途对话 + `min_hours_between` 已过
- **任一满足即可开睡**：进入 `windows` 区间 / 有未消费的睡眠信号 / 当日日志 ≥ `log_threshold_entries` / 手动
- `max_hours_between` 是**强制兜底**：即使没信号没窗口，超时也睡（防止长期不巩固导致记忆只增不减）
- 睡眠期间行为：`behavior_while_sleeping ∈ {silent, fast_reply, queue}`，默认 `silent`（睡了被 @ 也沉默）。**后台「睡眠」页可实时修改，无需重启**，改完对下一次判定立即生效；同时写入 `audit/admin.jsonl` 留痕

`request_sleep` 是**内置 C# 工具**，不进 Python 工具目录；它只写信号文件并返回"已记下，会找时间"，不阻塞对话。

### 6.2 分片调度（你的重点要求）

聊天记录可能极大，**绝不整份塞进子 AI**。用 map-reduce，以**水位线**而非日期驱动（I13）。

```
watermark = data/sleep/watermark.json  → {"last_consumed_log_ts": 1760000000, "last_consumed_msg_id": "..."}
```

`Chunker` 规则：

1. 扫描所有 `log/<date>/*.jsonl`，取 `ts > last_consumed_log_ts` 的记录，按 `scope` 分组
2. 单 scope 内按时间升序切分：**每片 ≤ 200 条 且 ≤ 24000 字符**
3. **片与片之间保留 10% 重叠**（约 20 条）——否则一个话题的前半句在上一片、后半句在下一片，抽取必然断裂
4. 每片独立产出一个 `chunk_id`，处理完立即写 checkpoint；进程崩溃后重跑只处理未完成片
5. 单次睡眠的**批上限**：≤ 40 片（超出留到下次，不要一次跑死）

### 6.3 四段流水线（I6）

```
[1 分流 map]   每片 → DistillAgent
                 输入：该片日志 + 该 scope 已有画像摘要（不是全文）
                 输出：受 schema 约束的候选条目数组，每项带
                       kind ∈ {identity,fact,preference,event,capability_gap}
                       text(≤120字) / tags / proposed_weight / confidence / evidence{message_ids}
                 硬约束：单次返回 ≤ 8 条、≤ 700 token；超限截断不重试

[2 归并 reduce] 全部候选 → MergeAgent（一次或分批）
                 职责：跨片去重、同一事件合并、冲突消解（新证据覆盖旧结论需 confidence 更高）
                 输出：待提交条目 + 待废弃条目(tombstone) + 候选人设改动(段级)

[3 校验 verify]  纯代码，不调模型
                 - pinned 条目不许删
                 - identity 段改动：是否超出修订预算、是否触碰 boundaries/output_rules
                 - capability_gap 不得写入人设（能力缺失不是人设缺失）
                 - 条目 schema 合法性、weight 区间、text 长度
                 - 生成 Python 工具时：契约完整性 + 静态检查（§7.2）

[4 提交 commit]  事务化：全部 diff 落 snapshot → 原子替换 → 更新水位线
                 任一步失败 → 整批回滚，水位线不动
```

**分流分类错误的代价最大**，所以第 3 段有一条硬规则：**`capability_gap` 类（"用户问我查天气我不会"）永远不进人设**，只进记忆条目与工具合成队列。否则人设会长出"我不擅长工具"这种自我否定。

### 6.4 快照与回滚（I9）

每次提批产出 `data/persona/history/<rev>/`：

```
<rev>/manifest.json     # 改了哪些文件、哪些条目、by=谁、trace_id
<rev>/System Prompt.md  # 该版本全文
<rev>/entries.patch.jsonl
<rev>/diff.txt          # 人读
```

回滚 = 用 `<rev-1>` 的全文覆盖 + 追加一条 `revert` 事件。后台一键操作，审计留痕。

### 6.5 巩固期间的行为

- 网关照常收消息、**照常写缓存日志**（I11 不受影响）
- 门控返回"睡眠中"，按 `behavior_while_sleeping` 处理
- 巩固与对话**不共享写锁**：巩固只写 `entries`/`persona`，对话只写 `log`，唯一交汇点是提交阶段的水位线与 store 替换（用 file replace 的原子性）

## 7. 工具子系统（Python）

### 7.1 执行

- `Runner`：`Process.Start` 起 `python -B <tool>/main.py`
- 输入：`stdin` 写 JSON 参数（一次写完关闭）
- 输出：`stdout` 读 JSON `{"ok":bool,"data":any,"error":""}`；`stderr` 只进日志
- 工作目录：`data/workspace/<session>/`，**工具的 cwd 不能是工具自己的目录**（避免互相读写）
- 超时：`contract.timeout_s`（默认 5s），超时 `Kill(entireProcessTree: true)`
- 环境变量：白名单传递（`PATH`, `PYTHONIOENCODING=utf-8`, `PYTHONUTF8=1`），不传任何密钥
- 并发上限：全局 4，按 scope 串行
- 失败一律收敛成文本回灌模型，**不炸对话**

### 7.2 静态检查（`Inspector`，注册与每次启用前都跑）

用 `python -c` 调 `ast` 做语法树扫描（C# 侧只调一次，不自写 Python 解析器），禁止：

- `import`：`os`, `subprocess`, `socket`, `urllib`, `requests`, `http`, `shutil`, `ctypes`, `importlib`, `sys`, `pickle`, `multiprocessing`
- 内建：`eval`, `exec`, `compile`, `__import__`, `open`（放行只读模式白名单路径另行评估，P0 直接禁 `open`）
- 属性：`__class__`, `__globals__`, `__subclasses__`, `__builtins__`

检查不过 → 状态直接 `disabled` + 原因写 `meta.json`，**不进入 active**。

### 7.3 注册与准入（I7）

**默认自动准入**（`config/tools.policy.json` 的 `auto_approve: true`）：不做人工审批，但**自动门禁一道都不能省**，任一不过即 `disabled`。

```
工具合成 / 手工放入
   → 写 tool.md（契约）+ main.py + meta.json{draft}
   → 门禁 1 契约完整性（name/params 类型/returns/timeout 齐备，名字不撞）
   → 门禁 2 静态检查（§7.2，含禁 open）
   → 门禁 3 沙箱冒烟试跑（用契约里的示例参数跑一次，超时 5s，须退出码 0 且 stdout 是合法 JSON）
   → 全过 → active（立刻进模型工具清单，下一次调用即可用）
   → 任一不过 → disabled + 原因写 meta.json.reject_reason，不进工具清单
   → 合成失败可重试（最多 3 次）
```

保留的手动通道：后台可对单个工具 `disable` / `enable` / 删除；`auto_approve:false` 时回退成 `pending` 等待人工批准。

**允许直接使用的前提下，这些护栏是不可选项**（它们不降低可用性，只降低事故半径）：

| 护栏 | 值 | 防的是 |
|---|---|---|
| 静态检查 | 禁 `os/subprocess/socket/urllib/requests/http/shutil/ctypes/importlib/sys/pickle/multiprocessing`、禁 `eval/exec/compile/__import__/open`、禁 `__globals__/__subclasses__/__builtins__` | 读走 `config/server.json` 里的模型 key 与 NapCat token |
| 沙箱 cwd | `data/workspace/<session>/`，**工具自己的目录与 `config/`、`data/persona/`、`data/memory/` 均不可读写** | 自我改写人设、篡改记忆 |
| 超时 | 契约 `timeout_s`，默认 5s，超时 `Kill(entireProcessTree)` | 卡死对话 |
| 环境变量 | 白名单传递（`PATH`/`PYTHONIOENCODING`/`PYTHONUTF8`） | 密钥泄漏到子进程 |
| 输出上限 | stdout ≤ 64KB，超出截断 | 单次回灌撑爆主上下文（I2） |
| 并发 | 全局 4，同 scope 串行 | 起一堆进程拖死机器 |
| 审计 | 每次调用记 `audit/tool.jsonl`（name/args 摘要/耗时/结果码/trigger trace_id） | 出事后无法复盘 |

**P0 范围限制**：P0 只做"注册与执行工具"，`ToolSmithAgent` 的自由生成放到 P4。理由：任意代码执行是全局最高危面，骨架没稳之前不打开生成通道；准入规则先建好并跑熟，等生成接上时门禁已经是现成的。

## 9. 错误码与降级

| 场景 | 行为 |
|---|---|
| 上报签名不符（x-signature / Bearer） | 401，计入 `audit`，不日志不建 trace |
| Body 非法 JSON | 200（避免 NapCat 重投风暴）+ 记错误 |
| 去重命中 | 静默丢弃 |
| DeepSeek 超时/5xx | 重试 2 次 → 兜底话术："我这边卡了一下，你再喊我一次" |
| DeepSeek 400/401 | 不重试；`silent` 降级 + 后台亮红灯（这是配置错误，不是偶发） |
| `thinking=disabled` 但 content 为空 | 记 `reasoning_tokens`，按 §2 的坑排查，兜底话术 |
| NapCat 发送失败 | 重试 2 次 → 丢弃并记 retcode（**绝不补发**，防刷屏与风控） |
| 工具超时 | 回灌"工具超时"给模型，模型自行决定换个说法 |
| 工具静态检查不过 | 该工具 `disabled`，不影响其他工具 |
| 巩固中途失败 | 整批回滚，水位线不动，下次重跑 |
| 巩固期间来消息 | 照常入日志，门控按 `behavior_while_sleeping` |

## 10. P0 验收用例

不连 QQ / 不连模型即可跑前 8 条（离线验收）：

1. 构造 OneBot 事件 POST → 200 且 < 2s 返回；日志文件出现该条记录
2. 同一 `message_id` 重投 3 次 → 日志 1 条、管线 1 次
3. `user_id == self_id` → 丢弃
4. 上报 token 错误 → 401
5. 发送成功后回写日志，`is_self:true` 且 `message_id` 为 NapCat 返回值
6. 限速：同群连发 5 条 → 发送间隔 ≥ 1s
7. 发言门：噪声消息 → `speak=false` 且写 gate 审计
8. Chunker：给定 5 万条日志 → 分片数正确、片间重叠 10%、超 40 片被截断并提示
9. 真实链路：群里 @机器人 "在吗" → 3~8s 内收到回复
10. 手动触发睡眠 → 产出条目 + 生成 rev + `diff.txt` 可读；`boundaries` 段 hash 未变
11. 人设编辑 → 回滚到上一 rev → 文件内容与快照一致
12. 沙箱 cwd 生效：工具读不到 `config/server.json`、`data/persona/`、`data/memory/`
13. 一个合法工具放入后**自动**走完 draft → 门禁三项全过 → active（无需人工），模型立刻能看到它的 schema
14. 一个 `import os` 或含 `open()` 的工具 → 自动 `disabled` + `reject_reason` 可读
15. 一个语法合法但冒烟试跑返回非 JSON 的工具 → 自动 `disabled`
16. 主动发言（无用户输入）也写入日志，`trigger=ambient`、`is_self=true`
17. 发送失败不写 chat log，只写 `audit/send.jsonl`
18. 杀掉进程再启动 → 水位线未前进、无重复条目（幂等）

## 11. 风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| 个人 QQ 号被风控/封号 | **高** | 限速 1 条/秒、冷却 90s、日预算、绝不补发、异常自动降为 `silent` |
| 模型生成代码执行 | **高** | P0 不开放生成；契约 + ast 检查 + 沙箱 cwd + 超时 + 输出上限 + 审计（自动准入，无人工闸，靠这七道） |
| 人设被单条输入劫持 | **高** | 日预算 1 次、confidence 累积、boundaries/output_rules 不可写、diff 可回滚 |
| 巩固分片导致记忆碎裂 | 中 | 10% 重叠 + reduce 跨片归并 + 每片带 message_ids 供回溯 |
| 子 AI 上下文膨胀 | 中 | 每 profile 硬 token 上限、超限截断不重试、返回 schema 化 |
| 内存工作集与持久记忆不一致 | 中 | 卡片 = 持久卡 ⊕ 今日日志尾部，今日覆盖持久 |
| 后台误操作毁掉记忆 | 中 | pinned 不可删、tombstone 只标记、全部写操作审计 + rev 可回滚 |
| DeepSeek 思考模式吞 token | 中 | 默认 `thinking:disabled`，仅 `think` profile 开启 |
| 沙箱阻止构建 | 低 | 已实测：`DOTNET_CLI_HOME`/`NUGET_PACKAGES` 重定向 + 手写 csproj + 零 NuGet |

### A.5 一个已知的语义边界

`identity` 段重写会占用当日修订预算（默认 1 次/天）。如果某次重写写歪了，当天不会再改，
需要到后台「人设」页用 diff / 回滚处理。这是 I4「自我一日一醒」的代价，不是 bug。

> **修订上限已改为可配置**：`config/persona.json` 的 `revision_budget_per_day`（0 = AI 不可写），
> 后台 `PUT /api/persona/budget` 实时改、不用重启。所以 I4 的实际含义是
> 「自我一次睡眠最多醒一次」，而不是「一天只能改一次」。

### A.6 记忆分层与物理分区（第二轮）

第一版把记忆做成了「一个会话一个 jsonl，只追加」——**这正是用户指出的问题**：碎片只增不减，
从来没有「反复巩固」。29 条里同一件事存三遍就是这个结构的必然结果。

改成两层 + 物理目录：

```
data/memory/
├─ shallow/<scope>.jsonl          浅层碎片（会被吸收、会过期）
├─ deep/person/<user_id>.md       人物画像：面向人、跨会话、慢过期
├─ deep/group/<group_id>.md       事件画像正文：面向群、会过期
├─ deep/group/<group_id>.json     事件画像 patterns（结构化，供发言门）
└─ archive/                       已吸收且过期的浅层碎片
```

**一次睡眠的正确流程**（改动后）：

```
1 分流   新日志 → 碎片 → shallow/
2 吸收   输入三份：现有 deep 画像 + 旧碎片 + 新碎片
         → 整段重写 deep/person/<uid>.md（归纳，不罗列）
         → 整段重写 deep/group/<gid>.md + 合并 patterns
3 标记   被用到的碎片打 absorbed=true，不再参与注入
4 抛弃   已吸收且超过 7 天的碎片 → archive/
```

关键点：**第 2 步的输入有三份**（第一版只有一份，所以永远不会「巩固」，只会「追加」）。

**两类画像的生命周期完全不同**：

| | 人物画像 | 事件画像 |
|---|---|---|
| 面向 | 人（跨会话跟着人走） | 群 |
| 半衰期 | 90 天 | 72 小时 |
| 上限 | 40 行 | 60 行 + 60 条 pattern |
| 用途 | 治碎片化 | 记住群体的梗/复读/固定话术 |

**事件画像 → 主动发言的反馈**（待第三批实现）：

```
weight = min(1, count/5) × exp(-距上次出现小时数 / 72)
finalScore = 模型意愿分 + min(boost_max, Σ命中 pattern 的 weight × boost_scale)
```

触发条件：`count ≥ group_pattern_min_count`（默认 2，出现过一次不算模式）。

### A.9 神经元观测（第四批）

三种可视形态里做了两种：

- **瀑布图**：一条消息一行，横向是各神经元的耗时条 —— 用来定位「这条为什么慢 / 为什么没回」
- **拓扑点亮**：固定拓扑 + 当天汇总计数，点某条消息会点亮它经过的神经元 —— 用来看结构与健康度
- **神经元连线图（不做）**：门控与记忆之间是代码写死的 `if`，没有可学习权重，
  画出来的线粗只能是手填常数，看着像脑图、信息量为零

**埋点设计**

每条消息一个 trace，管线里每个阶段一个 span：

```json
{"trace_id":"t_xxx","seq":0,"neuron":"gate","ts":1792977092,
 "ms":5,"ok":true,"stage":"noise","in_chars":7,"out_chars":0,
 "tokens":0,"brief":"noise score=0"}
```

落 `data/audit/spans/<日期>.jsonl`，保留 7 天（启动时清理）。

三条纪律：

1. **统一 trace id**：`Receiver` 生成后一路传到底，管线不再自己造一个
   （第一版有两套 id，日志与管线对不上，可视化做不了）
2. **静默也留痕**：门控判不说话照样写 span，否则可视化里会出现「消息凭空消失」的断流
3. **只记长度与摘要**：不把聊天正文抄进审计目录

一个语义细节：`gate` 的 `ok=false` 表示**判定过程出错**，不表示「决定不说话」——
后者是正常结论，用 `stage` 表达。

接口：`/api/trace/recent`、`/api/trace/{id}`、`/api/neurons/stats`。

### A.10 变化度（第五批）

**没有 loss，也不可能有。** LLM 是推理时系统：没有梯度、没有反向传播、没有参数更新，
模型权重一个字节都没动过。所谓「学习」完全是外部的——睡眠时改写人设与画像文件。
任何显示 `loss=0.32` 的界面都是编的。

但「它到底变了没有」是可以量化的，只是要问对问题。做了两层代理指标：

**① 自我变化率**（`data/audit/delta.jsonl`）

每次改写人设/画像时记录：

```json
{"ts":1793008935,"kind":"person","target":"10001","by":"sleep",
 "similarity":0.88,"addedLines":2,"removedLines":1,"absorbed":5,
 "note":"人物画像重写"}
```

`变化率 = 1 - similarity`。它回答：这次改写把自我改掉了多少。

**② 行为指纹**（`/api/behavior`，从聊天日志算）

光看文件变没变不够，因为模型会「说一套做一套」。所以还要看回复本身：

| 指标 | 含义 |
|---|---|
| 平均回复字数 | 话变长了还是变短了 |
| 括号率 | 回复里带「（动作）」的比例 |
| 问号率 | 反问多不多 |

**实盘第一组数据（10-25 与 10-26 对比）**：

| 日期 | 回复数 | 平均字数 | 括号率 | 问号率 |
|---|---|---|---|---|
| 10-25 | 23 | 57 | 4.3% | 39.1% |
| 10-26 | 64 | 36 | 10.9% | 21.9% |

括号率翻了一倍多——正是那天教它「用括号表达情感和动作」之后生效的。
这就是「变化感觉不到」的真相：**变化是渐进的，散在几十条回复里，单看一条察觉不到，聚合才看得见。**

**怎么用它诊断「变化太少」**

- 变化率长期 ≈ 0 但有新对话 → 吸收没生效，去查「深层记忆」页的画像有没有在更新
- 变化率忽高忽低 → 画像在震荡，不是在学习
- 人设变化率正常但行为指纹不动 → 改的可能是不影响表达的那一段（改 `style` 影响大，改 `identity` 影响小）

### A.10.5 深层画像的正确语义（重新巩固后修正）

第一次真正跑通「重扫全部日志」之后，暴露了三个碎片归属 bug 和一个**设计错误**：

| # | 问题 | 数据 |
|---|---|---|
| 1 | `capability` 碎片进了**别人的**人物画像 | 星涵画像里出现「我（AI）看不到图片」 |
| 2 | 私聊的 `event` 碎片永远吸收不掉 | 私聊 9 条 event 长期未吸收 |
| 3 | `identity` 碎片也永远吸收不掉 | 私聊 22 条 identity 长期未吸收 |
| 4 | **`patterns` 同一句话存了三个变体** | 「星璃你在吗」/「星璃你在吗 / 几点了」/「几点了」 |

**设计错误**（比三个 bug 更重要）：

第一版把深层画像做成了「只吸收未吸收的碎片」——那是**增量摘要**，不是画像。
后果是画像一旦写歪就永远纠不回来，因为证据里再也看不到相反的例子。

正确语义：

```
浅层 shallow     = 短期原料，7 天后归档
深层 deep        = 从「全部原料」反复归纳出的结论
absorbed 标记    = 只表示「这一轮处理过」，不是归纳时的过滤条件
```

所以每轮画像重写都从**完整碎片池**重新归纳（`Take(60)` / `Take(80)`），
`absorbed` 只用于「有没有新料决定要不要重写」和「标记进度」。
这样画像能收敛，也能在写歪之后自愈。

同时修掉的：
- 人物画像排除 `identity` / `capability`（那是「我」的事）
- 私聊 `event` 归人物画像、群聊 `event` 归事件画像（原本私聊 event 无人认领）
- `identity` 碎片并进人设后标记吸收
- pattern 归并改成「一方包含另一方即视为同一模式」，并用更短的形式作规范写法
- 人物画像 prompt 明令删掉描述「我」的句子（这样即使旧画像被污染，下一轮也会被清掉）

新增接口：`PUT /api/deep/person/{uid}`、`PUT /api/deep/group/{gid}`，可人工修正或清空画像让它重新归纳。

### A.10.6 思想层 P1 + P2

**P1 在线状态层**（`Core/Presence.cs`，不调模型）

判定优先级从高到低，这就是「AI 能不能主动找人」的全部规则：

| 优先级 | 来源 | 规则 |
|---|---|---|
| 1 | `manual` | 后台手动设，**不被任何自动判定推翻** |
| 2 | `self_report` | 话里出现「要睡了 / 在上课 / 在忙」→ 离线；「回来了 / 下课」→ 在线。带 TTL 自动失效 |
| 3 | `activity` | 最近 15 分钟说过话 → 在线 |
| 4 | `schedule` | 落进静默时段 → 一律离线 |
| 5 | `window` | 判不出来 → 按允许时段（默认 10:00-20:00）决定能否打扰 |

三层状态 `online / offline / unknown` 是分开的，因为 `offline` 是**硬闸门**（绝对不打扰），
而 `unknown` 还能按允许时段放行。这条设计直接解决「用户切换节点时 AI 凑上来」的问题。

内置工具也读它：`qq_send_private` / `qq_poke` / `qq_send_file_private` 对**第三方**发动作前会检查在线状态，
判为不可打扰就拒绝执行。正在跟某人对话时不算「主动打扰」（否则回复排队消息会被误拦）。

**P2 想法准入门槛**（`Core/IdeaLedger.cs`，不调模型）

不产生想法，只判断「这条想法现在能不能变成动作」。六道闸按顺序过：

```
总开关 → 意图白名单 → 静默时段 → 目标能否打扰 → 同对象冷却 → 每小时上限 → 每日上限
```

**每一条都记账**（无论放行还是拦下）到 `data/idea/ledger.jsonl`，
包括判定时的在线状态快照与被哪道闸拦下。没有这本账，就没法判断配额调得对不对。

实测（把目标手动设为在线后）：

```
第1条  allowed=true
第2条  allowed=false  cooldown  距上次打扰不足 6 小时（还剩 360 分钟）
群目标  allowed=true  presence=-   ← 群没有人的在线状态，不受 presence 限制
poke   allowed=false  intent     意图 poke 不在允许列表（speech）
```

**后台「思想层」页**：在线状态表（含手动设置/清除）、配额表单、今日准入计数、最近账本、
以及「投递一条想法」的闸门沙盒（只判定不执行）。

**还没做（P3/P4）**：发散与收敛本身。`interval_minutes` 目前只是占位配置。

### A.10.7 思想层 P3/P4 + 分段输出 + 追加

**P3/P4 发散与收敛**（`Core/IdeaEngine.cs`）

```
定时（interval_minutes）→ 只挑有对话活动的对象（群优先）→ 逐个想
   ↓ 发散（1 次模型调用，think 档）
      以人设 + 该对象画像 + 群 patterns + 最近 12 条对话为母题
      产出 0~3 个念头 {intent, target, text, reason}
   ↓ 收敛（1 次模型调用，merge 档低温度）
      挑 0 或 1 条；**允许 pick=null**
   ↓ 准入（P2 六道闸，纯代码）
   ↓ 执行 → 写聊天日志（trigger=idea）→ 记账
```

三条硬约束：

1. **发散不进主上下文**：这一层自己拼 prompt、用完即弃，绝不写回对话历史
2. **允许什么都不做**：收敛返回 null 是常态，prompt 里明说「没话找话是最糟的结果」
3. **说了就留痕**：念头、理由、最终说出口的话都进 `rounds.jsonl`，后台可查

预算：`think.max_rounds_per_hour` / `max_rounds_per_day` / `active_within_minutes`
（只有最近 N 分钟有对话才想，否则跳过）。

**运行可视化**：`GET /api/idea/status` 返回实时阶段（发散中/收敛中/发送中）、
阶段进度、下次发散倒计时、上次跳过原因、轮次预算、最近 30 轮的完整记录。
后台「思想层」页每 3 秒刷新。

**分段输出**：模型的换段是 `\n\n`，直接发出去在 QQ 里会变成一条塞两个自然段。
现在按空行切成多条消息，一条一句发出去（`Sender.Segment` + `SendSegments`），
条数上限 `reply_max_segments`（已从 3 提到 6）。记忆不受影响，记的是分段后的内容。

**追加机制**：主回复发完后，按权重决定要不要再补几句。

| 约束 | 值 |
|---|---|
| 一次连贯发言上限 | `burst.max_messages`（默认 10，含已发出的） |
| 继续追加概率 | `bas` × `decay^k`（默认 0.7 × 0.6^k，水位线越走越低） |
| 只在 `can_stop=true` 边界允许停 | 模型每条自带该标记，服务端**只在能自然收住处停** |

最后一条由服务端强制置 `can_stop=true`；若权重不够继续但话没说完，
会额外请求一句收尾，**避免「说一半因为权重停了」的断层**。

### A.10.8 四段可视化 + 主题归并 + 输入水位（第八批）

实盘反馈：「一直卡在一个思绪，而且思绪不随着我的回应和现在缓存记录更新」。
查完底下是三个独立的问题，不是一个。

**问题一：整句相似度归并根本无效（这个方向是错的）**

`TextSim` 是字符二元组 Jaccard。拿真实数据一验就露馅了：

| 相邻两版思绪 | 二元组 Jaccard |
|---|---|
| 「她好像习惯我在了，今晚该递的是句晚安。」vs「群安静得让人发慌…」 | 0.000 |
| 「她喊困却没走，我别急着追问…」vs「她那句困可能是想有人陪…」 | 0.000 |

后两句明明是同一件事，相似度是 0——因为「她喊/喊困/困却」和「她喊…」不共享任何
二元组。**整句比对抓不住「同一件事换了个说法」**，所以权重归并那套（阈值 0.7）
不能被照搬到思绪上。

改法：让收敛多产一个 `topic`（不超过 8 字的**具体事**标签，不是抽象感受），
归并比 `topic` 不比句子。比对次序：归一化相等 → 互相包含 → Jaccard ≥ 0.5。
阈值取 0.5 而不是 0.7，是因为「她喊困」和「她喊困了」的二元组 Jaccard 只有 0.67，
主题标签天生就短，短串的 Jaccard 系统性偏低。

`IdeaRound.TopicRepeat` 记录「这个主题连续第几轮」，`chain.topics` 存最近 6 个标签。
连续 ≥ 2 轮同题时，下一轮的母题里插一段：

> 【你在同一个地方已经卡了 N 轮】连续 N 版都落在「X」上。这一版不能再说这件事——
> 换一个完全不同的角度：换个人、换个时间段、换个动作，或者干脆想点别的。

**问题二：没有新输入还在想（原地踏步的真正来源）**

群安静、消息还是那几条，`interval_minutes=5` 一到就重新发散一遍。模型手上没有新料，
只能把同一句思绪换个说法交上来——看起来像在思考，其实在一个点上打转。
真实数据里连续 6 轮全是「她喊困」的变体，就是这么来的。

改法：`chain.last_input_ts` 记这一轮消费到的输入水位，下一轮若
`LastOtherMessageTs(scope) <= chain.last_input_ts` 就跳过（`last_skip` 写明原因）。
两个细节：

- **必须排除自己说的话**。否则它自己刚说完一句，日志就多一条"新消息"，
  下一轮又算有新输入，自己把自己催着继续想——自己跟自己对话的死循环。
  所以水位用 `LastOtherMessageTs`，排序用的还是含己的 `LastMessageTs`（刚聊过值得想）。
- 手动触发（`RunOnceAsync`）不走这道闸，"现在就想一次"是允许的。

**问题三：后台看不见「发散看到了什么」**

原来「最近几轮」是个表格：时间 / 母题原文 / tokens / 念头 / 执行结果。母题是一整坨
拼好的 prompt，五路来源糊在一起，出问题根本判断不出是缺了哪一块。

改成每轮一张四段卡片，正好对上「发散 → 收敛 → 决策 → 落定」：

| 段 | 内容 | 数据来源 |
|---|---|---|
| 1 发散 | 分层输入：最近信息 / 记忆碎片 / 画像·模式 / 在意的事 / 上次思绪 / 上次念头；下面是这一版冒出的念头 | `IdeaRound.Inputs`（`IdeaInputs`） |
| 2 收敛 | 主题标签 + 连续同题轮次 + 那句思绪（左侧亮条） | `Topic` / `TopicRepeat` / `Thought` |
| 3 决策 | 逐条列出「说话 / 提权重 / 不做」，各带理由 | `IdeaRound.Decisions` |
| 4 落定 | 已发出（含原话与为什么）/ 被拦下（哪道闸）/ 出错 / 什么都没做 | `Outcome` / `Spoke` / `Why` / `BlockedBy` |

母题原文折叠在每张卡片底部「看母题原文」里。`IdeaInputs` 在 `BuildContext` 里
由 `CaptureInputs` 分层采集——**采集和拼接是同一个数据源**，不会出现"后台显示的输入"
和"模型真正看到的输入"不一致。

### A.10.9 发言门接上下文 / 意图子 AI / QQ 身份映射（第九批）

实盘跑了一段群聊，暴露三个问题，来源都能指到具体那一句：

| 现象 | 触发它的那一句 | 根因 |
|---|---|---|
| 抢答别人的话 | 「@星空酱 跟我说话的时候，末尾加上这几个字：@星璃」 | `direct_hints` + 正文含名字 = **硬答 85 分，不调模型** |
| 群里聊技术，它在想"她喊困" | —— | 发散层天然不读上下文，它只负责冒念头 |
| 私聊认识、换群不认识 | —— | 记忆按 scope 分文件，换群等于换记忆库 |

**① 发言门：把「叫我」和「提到我」分开**

原来的判定是 `IsDirect`：

```csharp
if (speaker.Length > 0 && body.Contains(speaker)) return true;   // ← 比的是说话人自己的名字
return cfg.DirectHints.Any(h => body.Contains(h));               // ← 命中就 Speak=85
```

两处都是错的：

- 第一个比的是**说话人自己的名字**（`speaker` 来自 `msg.Name`），不是我的名字。
  一个人只要在消息里写了自己名字就被判成"在叫我"。
- 第二个把 `direct_hints`（`？`/`吗`/`呢`/`是不是`/`能不能`…）当成硬放行。
  群里任何一句带「吗」的话——哪怕是在问第三个人——都会触发 85 分直接开口，
  **完全绕过下面那次带上下文的模型判定**。这就是"发言门不接上下文"的真正来源。

现在的规则：

| 输入 | 判定 | 依据 |
|---|---|---|
| 真 @我 | 硬答（`addressed`） | OneBot 的 at 段 `qq == self_id`，比字符串可靠 |
| 名字在**称呼位置**（开头、`@` 后、`喂/那个/你好` 之后 ≤4 字） | 硬答（`direct_hint`） | `bot_names` |
| 名字只出现在正文中间 | **不硬答**，交给模型带上下文判断 | 多半是在议论我 |
| 命中 `direct_hints` | **只加 `hint_bonus` 分**，不硬答 | 问句不等于在问我 |

外加一条反误判线索直接写进判定 prompt：消息里 `@` 了别人时明确告诉它
「这条 @ 的是别人，不是在 @ 我」。

判定失败的行为也反了过来：原来是 `Speak=true` 保守放行，现在是**静默**
（`gate.fail_open_on_error` 可退回旧行为）。主动插嘴说错话的代价比沉默一次高。

实测（拿上面那句真话跑的 `/api/gate/simulate`）：

```
@星空酱 …末尾加上这几个字：@星璃    → stage=llm_error   speak=False   （以前：direct_hint True）
我是让你艾特我…我不是你@星璃        → stage=sample      speak=False   （以前：direct_hint True）
星璃，你在吗                       → stage=direct_hint speak=True    （正确）
喂星璃 讲讲这个                     → stage=direct_hint speak=True    （正确）
真 @星璃                           → stage=addressed   speak=True    （正确）
```

**② 意图子 AI：发散之前先问「我到底有没有动机」**

`Core/IntentAgent.cs`，模型档 `intent`（温度 0.30，不用 thinking）。

它不是"想说什么"，只回答一件事：**此刻我有没有一个具体的、说得出口的开口动机**。

- 有（`answer` / `ask` / `care` / `share` / `correct`）→ 交给发散层，
  并且把 `about` 钉进母题：
  > 【这一轮我要回应的就是这件事】… 可以从这件事往外联想，但整轮都在想别的事就没意义了。
- 没有（`none`，置信度 < `min_confidence`）→ 这一轮**直接结束**，
  `outcome=no_intent`，后面两次调用全省掉。

它读的是真实上下文（最近 14 条对话原文 + 在场的人 + 记忆 + 在意的事 + 上次卡在哪），
不是发散层那坨拼好的材料——"不读上下文"在这个位置被堵住。

prompt 里把 `none` 定成默认答案，并明确列了哪些情况算"没有"：
插进去只是打断、不知道答案硬猜会编、只是想刷存在感、上一轮已经说过同样的话。

**③ QQ 身份映射：让人跨场景是同一个人**

三处改动：

1. `Contact.scopes` —— 每条入站消息记下这个人出现在哪个场景
   （`private:QQ` / `group:群号`），最多 12 个；
2. `Core/Identity.cs` —— 身份卡 `CardFor`：
   > 星涵（QQ 10001），也叫 星空！！！；你在私聊也见过他。你对他的印象：星涵是星云游的技术总监…
   
   不管当前在哪个 scope 都注入，所以"换个群就不认识"这条被直接掐掉；
   群里额外给一份【在场的人】花名册（最近说过话的 ≤5 人，每人一行短卡），
   明确告诉模型"同一行说的是同一个号，别认错人"；
3. `ChatPipeline.RecallBlock` 的跨场景桥 —— 在群里说话时，
   额外从这个人的 `private:<uid>` 里捞最多 3 条未吸收碎片：
   > 【你私下里记着他的事】

验证：`/api/gate/simulate` 之后临时实例的 `data/contacts.json` 里
`10001 → scopes: group:100001`，说明映射确实在写。

### A.10.10 阈值交给模型，词表全部退场（第十批）

实盘又踩到两条，都指向同一个结论：

```
15:49:42 不发言 score=0 理由=灌水/表情 原因=规则判定为无意义消息      ← 那条消息就是「星璃」
15:50:16 不发言 score=30 理由=只是语气词，未点名，插话价值低          ← 那条消息是「emmm」
```

**直接叫名字被静默了**。根因是 `IsNoise` 的判据：抹掉噪声词之后剩下的字 ≤ 2 就算灌水。
「星璃」正好两个字——最纯粹的"在叫我"，被判成灌水，连模型都没送到。

这说明词表这套东西已经到极限了：`noise_words` 会误杀点名，`direct_hints` 会把别人的
提问当成在问我。两个方向都错，而且修不完。所以这一批把**阈值判定整体交给模型**：

| 原来 | 现在 |
|---|---|
| `noise_words` 抹词后长度 ≤2 判灌水 | 只判「有没有可判断的文字」：抹掉 `[图片]`/`[表情]` 这类协议占位符后还有没有字 |
| `direct_hints` 命中 → 硬答 85 分 | 整条删掉，词表退场 |
| `bot_names` 位置匹配判「在叫我」 | 交给模型：prompt 里给「我叫『星璃』」，问它 `addressed` |
| 群体加成折算成分数 | 只作为上下文（"群里正在被反复说的：X"）交给模型 |
| `sample_rate` 抽样跳过 | 删掉：逐条判定，成本由 `max_llm_calls_per_day` 兜 |
| 判定失败 `Speak=true` 保守放行 | 判定失败**静默**（`fail_open_on_error` 可退回） |

现在的流程：

```
真 @ / 私聊 ────────────────────────────────→ 直接回（不占主动额度）
有可判断的文字 ↓
模型判定 {addressed, score, intent, need_think}
   ├ addressed=true → 回（按被动回复，不看阈值）
   └ addressed=false → 走冷却 → 额度 → 阈值
```

`ambient_threshold` 会**写进 prompt**（"主动插话的门槛是 45/100，你按这个刻度打分"），
所以"阈值管理"这件事由模型在打分时自己对齐，而不是服务端拿词表往上加分。

`addressed` 字段同时进审计和沙盒返回，后台能直接看到"模型认为这句是不是在跟我说话"。

配置变化（`config/gate.json`）：

- 删掉 `noise_words` / `direct_hints` / `sample_rate` / `direct_threshold` / `hint_bonus`
  （类里保留属性以便旧配置仍能反序列化，但不再参与判定）
- `max_llm_calls_per_day` 从 200 提到 1500：现在每条消息都要判定，200 会在半小时内耗尽，
  然后整天静默。这是这一批唯一的真实代价。

实测（隔离实例）：

```
星璃                        → stage=llm_error   以前：noise        ← 修好了
emmm                        → stage=llm_error   以前：noise
[表情] / [图片]              → stage=noise       仍然正确
@星璃（…） 你好              → stage=addressed   speak=True 正确
```

后台「主动发言」页同步改了：删掉噪声词/直呼提示词/抽样率/被点名阈值四个表单，
加上「我的名字」（`bot_names`）——现在它是喂给模型的自我描述，不是匹配规则。

### A.10.11 配额保存 / 可私聊对象 / 发信人归属 / 双节点发散 / title+body 权重（第十一批）

五件事，第一件是真 bug。

**① 配额保存后不生效 —— PUT 把整份配置替换掉了**

`PUT /api/idea` 原来是 `body.Deserialize<IdeaConfig>()` 然后整份落盘。
前端只发 12 个顶层字段，`think` / `chain` / `burst` / `intent` 都没发，
于是这些子对象**全部回落到类默认值**——用户在后台点一次保存，
手写的 `think.max_rounds_per_hour` 就被静默重置成 6。表现出来就是"保存了不生效"。

改成深合并（`MergeConfig`）：只覆盖补丁里真的出现的键，嵌套对象递归合并。
`PUT /api/gate` 同样处理（原来改一个阈值会把 `groups` 覆盖一起清空）。

实测：

```
保存前  think.hourly=17
PUT {enabled:false, per_hour_limit:12, think:{max_rounds_per_hour:3, max_rounds_per_day:9}}
保存后  think.hourly=3  daily=9   chain.max_thoughts=4  burst.max_messages=10  intent.min_confidence=45
```

顺带修了「次数不更新」：`rounds_last_hour` / `rounds_today` 原来只数内存队列，
进程重启后是空的，配额闸门形同不存在。现在把 `rounds.jsonl` 的尾巴也读进来按 id 去重。
（实测重启后立刻显示 136/40，不再是 0。）

**② 「在线人」只认私聊过的人**

思想层最后要把想法落定成动作，最重的一档是私聊某人。群里说过话的人不一定加了好友，
拿他们当在线对象去挑目标，结果就是白想一轮、执行必然失败。

所以 `Contacts.IsPrivatePartner(qq)`：联系人里记过 `private:` 场景 →
有 `shallow/private_xx.jsonl` → 有 `log/<日期>/private_xx.jsonl`，三者任一即可
（后两条是对老数据的兜底，`scopes` 是后加的字段）。`/api/presence` 与
`IdeaEngine.PickTargets` 都按这个筛。（实测：5 个联系人里只有 1 个可私聊，列表就只出 1 个。）

**③ 发信人归属 + 唤醒机制**

群聊里最容易出的错是**把话记到别人头上**：A 发了张图，B 接着说了一句，回头那张图就变成 B 发的。

三处改动，全部是纯查表、不调模型：

| 层 | 改法 |
|---|---|
| 历史消息 | 每行前面加 `名字（QQ 号｜你私聊认识的）` / `名字（QQ 号）` |
| 唤醒块 | `Identity.WakeBlock` 把本场景最近说过话的人逐个对进联系人词典，正在说话的人排最前 |
| 占位符 | prompt 里明说「`[图片]`/`[表情]` 标在谁名下就是谁发的」；当前这条含占位符时再点一次 |

新进群时最需要这块——不然就是严重的失忆 + 发信人缺失。

**④ 发散拆成两路节点**

原来一次 `diverge` 调用吃一坨材料，它会挑好写的那一路走（群里聊接入口，它想"她喊困"）。现在拆开：

| 节点 | 只看 | 回答 |
|---|---|---|
| 上下文 | 自我 + 现在 + 最近对话 + 群体语境 + 意图锚 | **对方想让我做什么**（用户需求） |
| 记忆碎片 | 我在意的事 + 记忆碎片 + 画像 + 上一版思绪 + 卡住提醒 | **我自己在意什么**（自我意图） |

两路各写自己那半，合成 `thoughts` 再进收敛。两路互斥是有意的：
带了对方的话就会变回"回应"，带了自己的事就会跑题。

**⑤ 收敛双输出 + 权重改 title + body**

收敛输出从 `{thought, boost, action}` 变成 `{reply, intent}`：

```json
{"reply":"那句答复","topic":"...","why":"...",
 "intent":{"kind":"none|weight|act","target":"group:xxx 或 private:xxx",
           "who":"名字","text":"kind=act 的话","body":"kind=weight 的意向","reason":"..."}}
```

**权重为什么必须换结构**：老的权重是一句自由文本，靠字符串相似度归并，结果是累加不起来。
实盘里就是这五条各 0.20、谁也不比谁重：

```
她说困时多接一句，别急着劝睡（1.00）
下次想接话时别等，先蹬那两脚（0.20）
下次答这类事别只给干条，带点活人语气（0.20）
升级后留意自己说话和接话有没有变样（0.20）
升级前先把自己现在的状态和聊到的事记一下（0.20）
```

现在拆成两段：

- `Title` —— 枚举出来的落点：`在群里发言` / `和星涵私聊`（由 kind + who 推出，**不让模型自由发挥**）
- `Body` —— 一句话说清「我要和谁做什么、为什么」

累加的键是 `(Kind, Target)`，同一个落点直接相加，不再依赖文本相似。

外加一个**合并子 AI**（`Core/WeightAgent.cs`，模型档 `weight`）：
每次新意向进来，先把它和**当前所有未执行**的意向一起交给它，让它归并、相加、body 取更可执行的那句。
模型挂了就退回朴素合并（同键相加），不丢数据。

老数据自动迁移：`weights.json` 里 11 条旧格式全部转成 title+body，用 `legacy|id` 占位避免
全部撞到 `group|` 一个键上（撞了会 11 条只剩 1 条）。

**可视化**（思想层，都在「在线状态」上面）：

- **思想拓扑**：`意图 → 发散·上下文 / 发散·记忆碎片 → 合成思想 → 收敛 → 决策 → 加权意向`，
  每个节点显示最近一轮的真实内容；
- **耗时瀑布**：意图 / 发散·上下文 / 发散·记忆碎片 / 收敛 / 加权合并 五段的毫秒条；
- **加权意向**：title 徽标 + 权重条 + body，可「标记已执行」；
- **最近几轮**：收起时只有一行 `时间 · 对象 · tokens · 耗时`，点开才展开四段（最新一轮默认展开）；
- **在线状态**：一面 5 个，超出翻页。

新增接口：`GET /api/idea/weights`、`POST /api/idea/weights/{id}/done`、`DELETE /api/idea/weights/{id}`。

### A.10.12 发言门不认识自己 / 一次回复连答两个人（第十二批）

两个故障，第二个是 A.10.10 那次改动留下的隐患。

**① 「我不是星璃」——判定模型的自我描述是空的**

实盘后台里看到的两条判定理由：

```
理由=名字不符，非叫我
理由=叫的是星璃，我不是星璃      原因=意愿 0 < 阈值 60
```

翻配置就明白了：`config/gate.json` 里 `"bot_names": []`。
于是我写进 prompt 的自我描述是「我没有配名字（bot_names 为空）」，
模型读完得出「叫的是星璃，我不是星璃」，分数给 0，**整层静默**。

根因是这一层的地基压在一个**可被清空**的配置项上——`bot_names` 是 A.10.10 才加的，
只要有一次用旧版后台保存（旧 PUT 是整份替换语义）就会被回落到 `[]`。

三条修法，从根上不依赖那个配置项：

| 修法 | 说明 |
|---|---|
| 取值顺序 | `bot_names` → 人设【身份】首句里正则捞「我叫X」→ 兜底说明。人设在就永远知道自己叫什么 |
| 位置 | 自我描述**放到 payload 最前面**。原来塞在中间一行，模型会略过 |
| 可观测 | `GET /api/gate` 返回 `self` 字段，后台「主动发言」页直接把这段原文摆出来 |
| 启动自检 | `bot_names` 为空会在启动时告警，不再静默降级 |

实测（故意把 `bot_names` 清空）：

```json
"self": "你叫「星璃」。人设：我叫星璃，是星涵给我起的名字，我答应了，不改。…"
```

人设【身份】里那句「我叫星璃，是星涵给我起的名字」被正则捞出来当了名字。

**② 一次回复连答两个人**

实盘：

```
12:18:22 星涵：星璃，我是谁
12:18:32 Liebe：@星璃（…）你快问问群主什么时候v我50
12:18:33 星璃：星涵，你是星云游的技术总监…至于问群主v50，这事我不替你们转话。
```

星涵那句没被放行（主动插话没够阈值），紧接着 Liebe 的 @ 触发了被动回复，
**回复把两件事一起答了，还先对着星涵答**。看着就是"连一起了 / 把人搞混了"。

查过了 `InboundWorker`：没有批处理，也没有合并队列，一条消息一次处理。
所以不是发送层把整段聊天发出去了——是**这条回复到底在回谁**没约束住。

修法在提示词层，`ChatPipeline.BuildSystem` 末尾加一段硬规矩：

```
【怎么回】
- 只回应**最新这一条**。历史里别人问过、而你当时没答的，不要在这次一并补上。
- 一次只对一个人说话。同时有两个人在跟你说话，只回最新的那个。
- 谁说的就回谁。别把 A 说的事安到 B 头上，也别替 A 向 B 转话。
- 拿不准这句是不是在跟你说，就简短回一句「？」，不要猜着答。
```

对应的，主动发言那一层（`ConvergePrompt`）也加了一条：
群里发言时 `text` 不要点名回应某个具体的人，除非确定就是那一个；一条消息只对一件事。

**③ 附带修掉一个我上一轮引入的隐患**

`checkField` 只定义在 `gate.js`，我在 `idea.js` 里直接用了它，
结果「在线状态」和「思想层配额」两张卡片一起白屏（`ReferenceError` 在同一个 try 里被吞成"加载失败"）。
已补上，并加了一轮静态扫描（所有视图模块里被调用的名字 vs 本文件定义/import/参数/内建），
确认没有第二处同类问题。

### A.10.13 思想层空转 / 睡眠期失忆 / 分层唤醒 / 跨场景接续（第十三批）

用户看神经元报表问的四个"为什么"，逐个查了。

**① 思想 0 次 —— 一半是观测缺失，一半是真的空转**

先看数据：`data/idea/rounds.jsonl` 里今天 **175 轮**，其中：

| outcome | 轮数 |
|---|---|
| `no_intent` | 166 |
| `weight_only` | 4 |
| `no_idea` | 4 |
| `sent` | 1 |

两个问题叠在一起：

- **观测缺失**：`IdeaEngine` 注入了 `_tracer` 但**从头到尾没用过**，一个 span 都不写。
  报表按 span 聚合，所以「思想」永远显示 0 次——跑没跑都显示 0。已补：每轮在 `Finish()` 里写一个
  `neuron=idea` 的 span（`stage` = outcome，`brief` = 原因），实测立刻能出数。
- **真的空转**：95% 的轮次停在 `no_intent`。而这 166 轮每轮还要花掉约 1134 tokens
  去问意图子 AI「我该说话吗」，答"不该"。
  更糟的是**没动机时整轮直接 return**——发散层、加权层一次都没跑过，
  双节点发散和 title+body 权重等于没上线。

改法：意图只决定「要不要开口」，不决定「要不要想」。

```
没动机 → selfOnly：跳过「上下文」那一路（没东西可回应，硬凑只会产"硬找话说"的念头）
        → 仍然跑「记忆碎片」那一路
        → 收敛时把 act 明确禁掉，模型不听话就代码硬拦
        → 这一轮仍然可能产出「加权意向」，权重照常累加
```

意图判定本身失败（网络/解析）时反而要立刻收尾，不再白烧后面两次调用。

**② 记忆元 51 次 / 26ms —— 睡眠巩固期间记忆是"整个丢掉"的**

`ChatPipeline` 里原来是这一行：

```csharp
var memoryBlock = _sleepState.Sleeping ? "" : RecallBlock(...);
```

一次巩固实测 38 秒（12 个分片），这段时间里**所有回复的记忆注入都是 0 字**，
说话像个刚认识的陌生人。模型慢或网络抖的时候这个窗口会更长。
「人设偏离」「群聊私聊两码事」有一部分就是它。

改成瘦身版：睡眠期间仍然注入「这个人是谁 / 这个群是什么」两段轮廓（各 200~260 字），
只是不翻碎片、不做深层唤醒。

实测（同一条群消息）：

| 状态 | 记忆块 | 系统提示 |
|---|---|---|
| 睡眠中（旧） | **0 字** | 1763 字 |
| 正常（新，带分层唤醒） | **1200 字** | 2965 字 |

**③ 分层唤醒：浅层捞不到时往上叫一层**

原来只有"挑 5 条、够 0.18 分就注入"这一档。浅层碎片在新场景里经常是空的，
空了就一无所知地硬聊。现在按命中情况逐级升级：

| 档 | 内容 |
|---|---|
| 1 | 本场景浅层碎片（原行为） |
| 2 | 1 档空 → 这个人画像的**后半段**（前 500 字已注入）+ 跨场景私聊碎片 |
| 3 | 还不够 → 该场景**归档**记忆（`memory/archive/`，平时从不注入的老事），按关键词挑 3 条 |

新增 `Store.ReadArchive(scope)`。

**④ 群聊和私聊"完全两码事"**

根子是**历史按 scope 分文件存**：`log/<日期>/group_xxx.jsonl` 与 `private_yyy.jsonl` 互不相通，
换个地方聊，对话连续性直接断掉，同一个人显得像另一个人。

之前只补了"这个人的碎片记忆"，接不上"刚才聊到哪"。这一批补上原文：

- 群里跟**私聊熟人**说话时，把这个人私聊里最近 4 句**原文**捞进来
  （`【你私下里跟他说过的话】（换个地方聊，别当第一次见）`）；
- 记忆侧的跨场景桥 + 分层唤醒同时生效。

**⑤ 主动发言的人格为什么更松**

`IdeaEngine.CaptureInputs` 只从人设里取 `identity / style / interest` 三段，
**漏了 `boundaries`**——而聊天那一路（`BuildSystem`）是取全的。
所以主动发言说出来的话没有边界约束，人格明显比正常回复松。已补齐同一套段落。

### A.10.14 身份污染：同一个群内部的交叉污染（第十四批）

用户担心的是「跨块/跨场景前后矛盾」。查实际数据发现：**其中一部分根本不是跨场景问题，
是同一个群、同一个 scope 内部的记忆污染**，而且已经污染到会影响回答。

**实据一：`shallow/group_100002.jsonl` 里有两条互相否定的 identity**

```
{"kind":"identity","text":"我叫星璃，是对方给我起的名字"}
{"kind":"identity","text":"我叫星涵，是对方让我这样称呼他的"}     ← 污染
```

`identity` 的语义是「关于我自己」。`RecallBlock` 注入时把它标成「关于我自己」，
所以它真有可能拿"我叫星涵"来介绍自己。

**根因**：中文「（你可以）叫我星涵」是歧义的——
可以是"你给我起名叫星涵"，也可以是"你称呼我为星涵"。
`DistillPrompt` 明确写了「出现『叫你』『称呼』这类内容必须抽成 identity」，
于是模型把**对方的名字**抽成了**我的身份**。prompt 里那句"identity 只写我"压不住这个歧义。

**实据二：群画像把我自己算成了群成员**

```
deep/group/100002.md：
「这个群目前只有两个成员在互动：一个自称星璃，一个自称星涵。」
```

它把「我这台 AI」和「星涵」当成了群里的两个成员。

**修法（三层，从软到硬）**

| 层 | 改法 |
|---|---|
| prompt | `DistillPrompt` 之外补 `GroupProfilePrompt`：明确"你自己不是群成员"、提人要用「名字（QQ号）」 |
| **落库前硬校验** | `Consolidator.GuardIdentity`：identity 条目里断言的「我叫 X」，X 必须与已确认的自我名（人设【身份】+ `gate.bot_names`）一致；不一致就**降级成 fact 并归到说话人头上** |
| 注入侧分流 | `RecallBlock` 里 identity 条目按 `UserId` 分流标签：不是自己 → 「关于对方的身份（不是你）」 |

`GuardIdentity` 的正则刻意**不匹配「我是 X」**——「我是星云游的一份子」是自我描述，
把「星云游的一份子」当名字校验会误伤。自检：

```
「我叫星璃，是对方给我起的名字」        → 星璃     放行
「我叫星涵，是对方让我这样称呼他的」    → 星涵   降级为 fact
「我是星云游的一份子，话少」            → 不匹配   放行
「我是自学习AI，话少」                  → 不匹配   放行
```

**已就地修复的现存数据**（备份在 `%TEMP%\sga-cleanup-*`）：

- 删掉 `shallow/group_100002.jsonl` 里那条 `我叫星涵`
- `deep/group/100002.md` 里"两个成员在互动"那句改掉

**这一条对"跨块"讨论的意义**：真正的跨场景一致性问题是另一个（私聊说 A、群里说 B 没人管），
但**先要保证每个 scope 内部不烂**。scope 内已经会把自己的名字记错，
再谈跨 scope 一致就没意义。

### A.10.15 约定与边界 / 风格样本（卡尔曼式不确定度准入）（第十五批）

实盘案例（私聊 → 群聊的当场翻车）：

```
私聊  星涵：那…能不能再谈谈叫姐姐的事…
      星璃：你想听的话，我可以叫一声。但这不是我平时说话的样子，别当成常态。
      星璃：叫完你可别到处说。
      星璃：姐姐。
群里  星涵：星璃～出来让我抱抱～
      星璃：（走过去让你抱）姐姐。                      ← 当场就叫了
      星涵：你不是说别到处说嘛，怎么自己先说出口了～？
      星璃：我说的是「姐姐」和睡眠时间，没别的。        ← 编造解释
      星璃：不知道，我没法确认。名字和叫法都不算数。    ← 否认自己
      星璃：匿月，叫我星璃就行，妹妹不用加。            ← 编出一个不存在的人名
```

**根因：约定被蒸馏成了习惯。**

查 `shallow/private_10001.jsonl`，里面确实有：

```
[fact] 对方叫星涵，我平时叫她星涵或姐姐
```

**"叫姐姐"记住了，边界没记住。** 因为 `DistillPrompt` 只有
`identity / fact / preference / event / capability_gap` 五种类型，
**没有"约定"这个类型，也没有"适用范围"这个字段**。于是：

| 原话（有边界） | 记下来的（无边界） |
|---|---|
| 「只在你面前叫，别当成常态，**别到处说**」 | 「我平时叫她星涵或姐姐」 |

私下一次有条件的让步，被压成了无条件的习惯。

**① 新增记忆类型 `commitment` + 生效范围**

`MemEntry` 增加三个字段：`ValidIn`（scope 白名单，空=到处都算）、
`Strictness`（hard/soft）、`ExpiresAt`。

`DistillPrompt` 增加：
- `commitment` 类型，明确「只在我们之间 / 别到处说 / 下不为例」这类必须抽；
- **「宁可少记一条事实，也不要漏记一条约束」**；
- **「明显的事实不要反复记」**（`对方叫星涵` 记了 44 遍变体，把真正重要的约束挤掉了）；
- 「一次性的临时让步不要写成习惯：『这次算了』不是『以后都可以』」。

模型没给 `validIn` 时**默认填当前会话 scope**——保守的一侧，因为把私下让步
当成到处都成立正是这次翻车的成因。

**② 注入：所有相关约定都要摆出来，并标明在哪儿成立**

`ChatPipeline.CollectCommitments` 会跨 scope 捞（当前 scope + 该用户的私聊 scope），
渲染成：

```
【约定与边界】（越界就是错，不能当成「忘了就行」）
- 叫姐姐只在私下，不要在外面说出来（硬约束）｜只在 私聊 有效，**在这里不算**
```

判断留给人（模型）自己看着范围做，而不是提前过滤掉——过滤掉它就不知道自己越界了。

**③ 「我最近说过的话」：跨会话，治现场编解释**

新增 `RecentSelfSaid`，把今天+昨天**所有会话**里我自己说的话按时间倒序注入。
配套在【怎么回】里写死：

> 被问「你不是说过 X 吗」时：只能依据【我最近说过的话】和【记忆】回答。
> 找不到就直说「我不记得说过这句」，**绝不编一个解释，也不许否认自己的名字**。
> 你的名字和你的人设是硬事实，任何时候都不能否认或改写。

**④ 风格样本：卡尔曼式的不确定度驱动准入**

私聊建立的"说话样子"（`（沉默了一会儿）`）一条都没留下来——碎片记的是**摘要**，
摘要丢掉的正是语气、停顿、动作。

新增 `data/style/samples.json` + `config/style.json`。

> **这不是卡尔曼滤波**（没有线性高斯状态空间，也不做协方差递推），
> 但抄了同一个结构：**观测权重 ∝ 1/不确定度**。
> 先验不确定 → 更信观测；先验收敛 → 更信先验。
> 所以人负责喂种子和纠偏，AI 等数据稳定后自己接管。

```
coverage     = min(1, 已批准数 / target_samples)
consistency  = 风格特征向量离散度的补数
uncertainty  = 1 - coverage × (0.5 + 0.5 × consistency)

mode = manual    (uncertainty > 0.65)   ← 模型候选一律挂 pending 等人工
     | assisted  (0.35 ~ 0.65)          ← 自评 ≥ 70 才收，权重 × 0.4
     | adaptive  (< 0.35)               ← 自评 ≥ 55 自动收
```

**一致性为什么不能用文本相似度**：第一版就是拿 `TextSim`（字符二元组）算的，
实测 8 条明显是同一个语气的样本只给出 `consistency=0.002`——

```
（沉默了一会儿）你想听的话，我可以叫一声。
（没接话，耳朵有点热）
```

字面上几乎没有共同二元组，但谁看都知道是同一个人的话。
这和 A.10.8「整句相似度抓不住同一主题」是同一个教训：**风格不是词汇重叠**。

改成**结构特征向量**（6 维）：开口是不是括号动作、动作占比、长度、
爱不爱用省略号、爱不爱反问、有没有第一人称。看结构不看词汇。

实测模式迁移：

| 样本 | mode | uncertainty | coverage | consistency |
|---|---|---|---|---|
| 0 条 | manual | 1.000 | 0 | 0 |
| 3 条（同风格） | manual | 0.697 | 0.375 | 0.614 |
| 8 条（同风格） | **adaptive** | 0.152 | 1.0 | 0.697 |
| 9 条（掺一条公文风） | adaptive | 0.255 | 1.0 | 0.49 ↓ |

**ab 混合怎么落地**：
- (a) 人工喂 → `POST /api/style` 直接 approved，权重 1.0，后台可改判/删除；
- (b) 模型自评 → **在睡眠巩固时**从私聊片段里挑我自己的回复，
  让模型打「像不像我平时的样子」，再交给 `Propose()` 按当前不确定度决定收不收。
  放在巩固阶段是为了不占用对话延迟——"像我吗"本来就是个慢问题。

**⑤ 验证**

- A/B 实测约定注入：有约定 `记忆=1254字`，删掉那条 `记忆=1200字`，差 54 字 = 约定块
- 模式迁移表格见上
- DI 解析、`/api/style`、`/api/idea` 全部正常

### A.10.16 分块层（observe 模式）+ 两个后台页面（第十六批）

**① 两维正交**

```
Entity（谁）  —— 全局，跨 scope、跨块。去 Contacts / deep/person 里取，块只引用不复制
Block（事）   —— 每个 scope 内多块并存。只是"上下文边界"，不持有画像
交叉点        —— Block.Participants 是 entity_id（QQ 号）的引用列表
```

因为正交，"同一个人同时两条主线"不是需要取舍的设计决策，而是模型天然允许的状态。

**② 块模型**（`Core/Dialogue.cs`，`data/dialogue/<scope>.json`）

```
DialogueBlock { Id, Scope, State, Participants[], Owner, Topic,
                CreatedAt, LastActiveAt, MessageCount, MessageIds[], LastUserId }
State: one_to_one | open_topic | cold | closed
```

`State` 直接导出回复形态（一对一 vs 对大家）——**不需要额外的"广播开关"**，
这就是"保留对群说话能力"的实现方式。

**③ 路由**（`Core/DialogueRouter.cs`）

```
规则信号累加 → 最高分 ≥ min_confidence → continue(那块)
             → 不到门槛 → 问模型（use_model）
             → 模型也判不了 → unresolved（**静默，不硬猜**）
没有任何块 → new_block
```

信号与权重（全部可配）：同一个人接着说 0.45 / reply 同一块 0.40 / @ 同一人 0.50 /
实体重叠 0.25 / 指代词 0.30 / 时间接近 0.20。

**第一次实测就抓到一个设计漏洞**：只用最初那五个信号时，4 条消息里 3 条判不了（75%）——

| 消息 | 得分 | 缺了什么 |
|---|---|---|
| 「接入方案我改了一版…」 | new_block | 第一块 |
| 「嗯，我看看」 | 0.20 | 只有时间接近 |
| 「我**那个**也改完了…」 | 0.49 | 指代词 0.30 + 时间 0.20 |
| 「就是拿你这版当底改的」 | 0.19 | 只有时间接近 |

**缺的是"同一个人接着说"这个最强、最便宜的信号。** 补上 `w_same_sender=0.45` 之后：

```
9500001 星涵  → new_block
9500002 星涵  → continue  0.646   ← 同人 0.45 + 时间 0.20
9500003 Liebe → unresolved 0.497  ← 正确！没 reply 没 @ 没指代，拒绝硬塞
9500004 星涵  → continue  0.643
判不了比例 0.75 → 0.25
```

注意 9500003：它**正确地**判不了，而不是被硬塞进星涵的块。这正是"判不了就静默"的价值。

挂在 `ChatPipeline.ProcessAsync` 的最前面，**在发言门之前**——因为被门拒掉的消息

### A.8 记忆去重：为什么不能靠降阈值

第一轮实盘后记忆库出现明显重复（同一件事存 2~3 条）。用真实数据实测字符二元组 Jaccard：

| 相似度 | 两条陈述 | 是否同一件事 |
|---|---|---|
| 1.000 | 装傻时说“诶嘿～” / 装傻时说「诶嘿～」 | 是 |
| 0.957 | 生日9月19日 / 生日9月19 | 是 |
| 0.903 | …三次元之间的桥梁，做二次元沉浸式… / …桥梁，做沉浸式… | 是 |
| 0.818 | 需要对方描述图内容 / 描述图里的内容 | 是 |
| 0.714 | 最常用Unity / 主要用Unity | 是 |
| 0.474 | 是星涵给我起的名字，我答应了 / 是对方给我起的名字 | 是 |
| **0.9+** | **生日9月19日 / 生日10月19日** | **否（不同事实）** |
| **0.9+** | **大二学生 / 大三学生** | **否（不同事实）** |

结论：**中文短句的措辞差异可以把相似度压到 0.5 以下，而一字之差的不同事实相似度反而有 0.9。**
所以「调低阈值自动合并」会静默吃掉真事实，比留几对重复严重得多。

采取的方案：

1. **自动合并只做保守判断**：精确相同，或 `Jaccard ≥ 0.85`，**且数字序列必须一致**
   （数字守卫专门挡「9月19 vs 10月19」这类）
2. **0.55~0.85 的灰区不自动合并**，由 `GET /api/memory/duplicates` 列出来人工判断，
   再 `POST /api/memory/merge {scope, keep_id, drop_ids}` 合并
3. **`POST /api/memory/dedupe`** 一键清理「去掉标点后完全相同」的条目（纯字符串相等，零语义风险）

### A.3 实现中与本文档的偏差（以代码为准）

1. **配置文件用 snake_case**。`AppJson.Config` 对磁盘配置与后台 API 统一 snake_case，内部运行时文件（persona meta、tool meta、entries）仍是 camelCase。
2. **凭据拆到 `config/secrets.json`**，`server.json` 不含任何 token。
3. **静态检查放行 `sys`**。Python 工具读 stdin 必须 `import sys`；改为禁 `sys.modules` / `sys._getframe` / `settrace` / `setprofile` / `path_hooks` / `meta_path` 等属性。`open` / `os` / `subprocess` / 网络库仍然全禁。
4. **`sys` 之外，Windows 系统必需的环境变量**（`SystemRoot` 等）在代码里强制保留，否则 Python 连随机数都初始化不了。
5. **日志 `ts` 用本地接收时间**，事件自带时间另存 `event_ts`。避免 NapCat 补投的历史时间戳把数据写进旧日期目录、导致水位线漏读。
6. **`GET /` 需要单独端点**。`POST /` 已被上报占用，否则路由会判 405。
7. **人设 rev 0 = 出厂基线**，首次读取时自动落盘；`rollback/0` 恢复出厂。
8. **巩固失败不推进水位线**（重要修正）：任一分片蒸馏失败即中止，且提交前与库内已有条目去重，保证重跑幂等。
